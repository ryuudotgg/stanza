The [braces](/rules/braces) rule removes the braces around a single statement control flow body. It keeps them where removing them would change parsing (a dangling `else`, a declaration as the body, a statement without a trailing `;` that the next line could continue) and where the block holds a comment. The rule page lists every case. A body that fits goes onto its header line, and every other line break is left to the formatter.

## Lint Config

A repo that enforces braces through its linter keeps them, so Stanza does not fight the lint rule. Without a flag, Stanza walks up from each file's directory and reads the lint config it finds:

- flat ESLint (`eslint.config.*`) and legacy ESLint (`.eslintrc*`, `eslintConfig` in `package.json`): the `curly` rule;
- Biome (`biome.json`, `biome.jsonc`, `.biome.json`, `.biome.jsonc`): `linter.rules.style.useBlockStatements`, the `style` group turned on, `preset: "all"` in `linter.rules` or `linter.rules.style`, or `all: true`, at the top level or in an override. As in Biome, `useBlockStatements` and the group's severity beat the style preset, which beats the root one. A brace setting anywhere else makes the config unknown, since Biome rejects it;
- Oxlint (`.oxlintrc.json`, `.oxlintrc.jsonc`, `oxlint.config.ts`): `curly` or `eslint/curly`, `categories.style`, and `overrides`.

`files`, `ignores`, `excludedFiles`, `excludeFiles` and `includes` scoping applies per file, matched against the file's own path, so a config that enforces braces only under `src/` or only for `**/*.config.ts` leaves the other files to the rule. A pattern Stanza cannot match exactly, such as `src/[ab].ts`, keeps braces wherever it might apply. Any config that enforces braces, or that Stanza cannot read, keeps braces.

A YAML config (`.eslintrc.yaml`, `.eslintrc.yml`, or an extensionless `.eslintrc` that is not JSON) gives the same answer as the same tree written as JSON. Stanza reads one YAML document in a plain subset: block and flow maps and lists, string keys, single line plain or quoted values, and `#` comments, up to 1 MiB, 64 levels of nesting and 100,000 nodes. Anchors, aliases, tags, merge keys, multiline and block scalars, directives, more than one document, duplicate keys, tabs in indentation and anything else outside that subset make the whole file unknown, even under a key Stanza does not use. An extensionless `.eslintrc` is read as JSON with comments first, then as YAML, under the same limits, and a duplicate key there makes it unknown too.

A plugin preset counts like the config's own rules. Stanza reads `plugin.configs.<name>` from a plugin the config imports or requires, finding the package from that config file. It reads `plugin:<name>/<config>` in a legacy `extends` from the plugin package found from the directory of the `.eslintrc` or `package.json` that ESLint started from, as ESLint does. A preset whose package is not installed, or whose value Stanza cannot read without running it, keeps braces.

When a config is unknown and no config turns braces on, Stanza prints one line on stderr per run:

```text
stanza: cannot tell whether <files> enforces braces, so braces stay; pass --braces or --no-braces to settle it
```

Under `--fix --stdin --json` stderr carries the findings, so the notice is not printed there.

## Flags

`--braces` turns the rule on even where lint config turns it off or Stanza cannot read the config. `--no-braces` turns it off and keeps the blank line rules. With either flag the config is not read and no notice prints. Passing both is a usage error. `stanza hook` takes `--braces`, `--no-braces` and `--hunks` in its command. See [CLI](/reference/cli).
