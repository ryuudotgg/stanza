Stanza formats statement lists: the module top level, function bodies, arrow block bodies, methods, static blocks, `if`, loop and `try` blocks, and switch clause bodies. The blank line rules never touch the gaps between class members or namespace members.

At top level the rules read `export const` and `export function` as the declaration they export, so a constant joins the exported function that reads it. Imports and re-exports (`export ... from`) form one group: a multi-line import gets no blank line before the next import, and imports never count toward a [wall](/rules/wall). [short-body](/rules/short-body) and [edge-blank](/rules/edge-blank) are block rules and skip the top level.

`--fix` prints these findings too. It never changes the code for them.

A statement is compact when it sits on one line, or when it is a braceless `if` without `else`, `for` or `while` whose joined line fits the formatter width. [short-body](/rules/short-body) covers the details.

Stanza reads the width for each file. The nearest oxfmt, Biome or Prettier config that applies to it wins, including overrides. If that config sets no width, Stanza reads `.editorconfig` where the formatter does. Otherwise it uses the default width of the formatter the nearest `package.json` that lists one depends on: 100 for oxfmt, 80 for Biome or Prettier. With no formatter anywhere, it uses 80. When one directory has configs for two formatters, that dependency picks one, and when it does not, the smaller width wins. Tabs count as the formatter's tab width. `stanza explain` prints the width and where it came from.

## How a Gap Is Decided

A gap is the space between two neighbouring statements in a list. One rule decides each gap. The rules are tried in a fixed order, and the first one with an opinion wins:

1. [short-body](/rules/short-body)
2. [guard-chain](/rules/guard-chain)
3. [after-multiline](/rules/after-multiline)
4. [switch-clauses](/rules/switch-clauses)
5. [guard-join](/rules/guard-join), [consume-join](/rules/consume-join) and [use-join](/rules/use-join)
6. [after-guard](/rules/after-guard)

When none of them applies, the gap keeps the blank lines it has. [let-step](/rules/let-step) runs afterwards as a pass over the decided gaps. [edge-blank](/rules/edge-blank) looks at the space inside a block's braces rather than between statements, and [braces](/rules/braces) runs on its own. A gap next to a statement under `stanza-ignore` is frozen: no rule touches it or reports it (see [Directives](/rules/directives)). A statement that starts on the closing line of a multi-line statement is left alone.

Comments stay attached to the statement below them as long as no blank line separates them. An inserted blank line goes above the leading comments, and a trailing comment on the same line moves with its statement. When a blank line already separates a comment from the statement under it, the statement is detached: the gap above it is never edited or reported.

`stanza explain <file>:<line>` prints the rule that decided a line and what it outranked. See [Explain](/reference/explain).
