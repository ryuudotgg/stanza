Applies to the block owned by an `if` (the consequent or the `else`) and by any loop, at any depth, module top level included. When the block holds exactly one statement of a removable kind (an expression, `return`, `throw`, `break`, `continue`, a nested `if` or a loop), the braces go. Only the braces go: Stanza never reflows the code inside, so a body that sat on its own line stays there, and line breaking is left to your formatter. `do { tick(); } while (busy)` loses its braces too. In the example the `for` keeps its braces because its block holds two statements. [Braces That Stay](#braces-that-stay) lists every case.

A statement under `stanza-ignore` keeps its own braces, `else if` chain and label included, while the code nested inside it is still formatted (see [Directives](/rules/directives)). `--no-braces` turns the rule off, and so does a lint config that enforces braces. [Braces and Lint Config](/rules/braces-and-lint-config) covers both.

Removing braces changes which statements are compact, so the blank line rules see the unbraced code. When unbracing leaves a body of two or three compact statements, [short-body](/rules/short-body) removes the blank lines between them.

## Braces That Stay

The `else` branch loses its braces. The outer `if` keeps them because its body ends in an `if` without `else`, and the `while` keeps them because of the comment.

<Accordions>

<Accordion title="Not exactly one statement">

The block holds two or more statements, or none, like the `for` in the first example.

</Accordion>

<Accordion title="A statement of another kind">

The statement is a declaration (`const`, `let`, `var`, a function, a class), a nested block, a `switch`, a `try`, a labeled statement or an empty statement.

</Accordion>

<Accordion title="No trailing semicolon">

The statement has no trailing `;` and the next code could continue it: the next token is on the same line, or the next line starts with `(`, `[`, a backtick, `+`, `-`, `/`, `.`, `<` or `;`.

</Accordion>

<Accordion title="A comment inside the braces">

A comment sits inside the braces but outside the statement, like `// drop the last one` in the `while` above.

</Accordion>

<Accordion title="A comment after the closing brace">

A comment follows a `}` that sits alone on its line, as in `} // note`.

</Accordion>

<Accordion title="A dangling else">

Removing the braces would leave a dangling `else`: the statement ends with an `if` that has no `else`, and an `else` follows the block, like the outer `if` above.

</Accordion>

<Accordion title="Two words that would fuse">

Removing the braces would fuse two words, as in `else{a();}`.

</Accordion>

<Accordion title="Text that would not parse">

The unbraced text would no longer parse.

</Accordion>

</Accordions>
