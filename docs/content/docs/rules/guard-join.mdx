---
title: guard-join
description: The blank line between a value and the if that checks it.
---

<RuleSummary />

<DiffExample fixture="guard-join/example.ts" />

Applies when a single-line declaration (`const`, `let` or `var`, plain or destructured, every bound name counts) or a single-line assignment is followed by an `if` that reads one of the names it binds. The blank line between them goes. The size of the `if` body does not matter and an `else` does not matter: the `if` is the step that consumes the value, so in the example the two statement block still joins `const record`. `let count: number;` followed by an `if` that assigns `count` joins too.

[short-body](/rules/short-body) outranks it and removes the blank anyway. [after-multiline](/rules/after-multiline) outranks it the other way: a declaration that spans lines keeps a blank line after it, however clearly the `if` reads it. A gap next to a `stanza-ignore` statement is frozen and never joins.

<Accordions>

<Accordion title="Reads inside a nested function">

A read that only happens inside a nested function does not count: `if (ok) run(() => record)` does not join to `const record`.

</Accordion>

<Accordion title="Shadowed names">

A name shadowed inside the `if` does not count as a read of the declared name.

</Accordion>

<Accordion title="Member paths">

An assignment to a member such as `state.count = read()` joins when the `if` reads the same path, `state.count`. Reading `state.counter` does not count.

</Accordion>

</Accordions>
