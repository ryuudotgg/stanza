title: Codex
description: Fix each file Codex patches, and the files it patched when a turn ends.

<Callout type="info">
  Codex runs a hook only after you trust it with `/hooks`, and a project hook also needs the project
  trusted. If your `hooks.json` already has a `hooks` object, add these entries to it.
</Callout>

`stanza hook` runs as two Codex hooks: PostToolUse on `apply_patch`, and Stop. Put this in `~/.codex/hooks.json` for every repository, or in `.codex/hooks.json` at the root of one:

```json tab="Global" title="~/.codex/hooks.json"
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "apply_patch", "hooks": [{ "type": "command", "command": "stanza hook" }] }
    ],
    "Stop": [{ "hooks": [{ "type": "command", "command": "stanza hook" }] }]
  }
}
```

```json tab="Project" title=".codex/hooks.json"
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "apply_patch", "hooks": [{ "type": "command", "command": "stanza hook" }] }
    ],
    "Stop": [{ "hooks": [{ "type": "command", "command": "stanza hook" }] }]
  }
}
```

## On Patch

After `apply_patch` lands, Stanza runs one `--fix` pass over the files the patch added, updated or moved. When that changes a file, Codex is told to read it again before editing it. A patch that failed gets no pass.

## On Stop

When Codex ends its turn, Stanza reads the session rollout and runs one `--fix` pass over the changed files Codex patched this session. Files you edited by hand stay untouched. If Stanza does not recognise the rollout, it falls back to every changed file in the repository. If findings remain that `--fix` cannot apply, the turn does not end: Codex gets the findings with a line per rule explaining it, fixes them, and replies again.

## Flags

`--braces`, `--no-braces` and `--hunks` go in the command, as in `stanza hook --hunks`. In a repository whose existing code does not follow the rules yet, see [Existing Codebases](/guides/existing-codebases).

[Hook Protocol](/reference/hook-protocol) has the full input, output and exit status.
