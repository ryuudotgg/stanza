<Callout type="info">
  Codex runs a hook only after you trust it with `/hooks`, and a project hook also needs the project
  trusted. An untrusted hook is skipped without a warning, and editing its entry makes it untrusted
  again. If your `hooks.json` already has a `hooks` object, add these entries to it.
</Callout>

`stanza hook` runs as three Codex hooks: PostToolUse on `apply_patch`, Stop, and SubagentStop. Put this in `~/.codex/hooks.json` for every repository, or in `.codex/hooks.json` at the root of one:

## On Patch

After `apply_patch` lands, Stanza runs one `--fix` pass over the files the patch added, updated or moved. When that changes a file, Codex is told to read it again before editing it. A patch that failed gets no pass.

## On Stop

When Codex ends its turn, Stanza reads the session rollout and runs one `--fix` pass over the files Codex patched this session. A file Codex already committed is still checked, unless `--hunks` is set and the file has no change since HEAD. Files you edited by hand stay untouched, so a session with no completed patch changes no file. If Stanza does not recognise the rollout, it falls back to every changed file in the repository. If findings remain that `--fix` cannot apply, the turn does not end: Codex gets the findings grouped by file, each with its line and rule, fixes them, and replies again. The same message names every file Stanza rewrote, so Codex reads those again first.

## On SubagentStop

When a subagent finishes, Stanza reads that subagent's own rollout and runs the same pass over only the files it patched. Files the main session or other subagents patched wait for their own pass, and a subagent with no completed patch changes no file.

## Flags

`--braces`, `--no-braces` and `--hunks` go in the command, as in `stanza hook --hunks`. In a repository whose existing code does not follow the rules yet, see [Existing Codebases](/guides/existing-codebases).

[Hook Protocol](/reference/hook-protocol) has the full input, output and exit status.
