---
title: Explain
description: Ask which rule decides a line, and why.
---

```
stanza explain [--no-braces] [--] <file>:<line>
```

`stanza explain` explains the gap that ends at a line and the braced body that starts there. It changes nothing.

## A Gap

For a gap it prints the two statements, the rule that decided, what it found (the name a declaration binds and the statement that reads it, a guard, a statement spanning several lines), the rules it outranked and what `--fix` would do.

When either statement is a braceless two line `if`, `for` or `while`, it also prints `width:`. This names the width in columns, its config or default source, and the joined length of each such statement. The line says whether it fits on one line.

Given this file at `src/load.ts`:

<include lang="ts" meta='title="src/load.ts" lineNumbers'>
  ../../../../tests/fixtures/after-multiline/example.before.ts
</include>

`stanza explain src/load.ts:5` prints:

```text title="Output"
src/load.ts:5

gap above line 5, no blank lines
  2-4      const raw = JSON.parse(
  5        if (!isRecord(raw)) throw new Error("config must be an object");
rule:      after-multiline, wants a blank line
because:   the statement above spans lines 2 to 4
outranked: guard-join, wants no blank line: `raw` is bound on line 2 and read by the `if` below it
result:    --fix adds a blank line
```

## A Braced Body

For a single statement body it says whether `--fix` removes the braces or why they stay:

- code after the body could continue the statement,
- a comment sits inside the braces,
- `--no-braces` was given,
- or a lint config file enforces braces, named in the output (see [Braces and Lint Config](/rules/braces-and-lint-config)).

## Options

It takes only `--no-braces`. It explains a file even when `--fix` and `--check` would skip it as generated or excluded, and ends with a note saying they skip it.

Use `--` before a path that starts with `-`, such as `stanza explain -- -draft.ts:5`. Flags must come before `--`. Arguments after the first `--` are literal, including `--no-braces` and any further `--`. Exactly one `<file>:<line>` location is required.

## Exit Status

| exit | meaning                                                                                   |
| ---- | ----------------------------------------------------------------------------------------- |
| 0    | something was explained                                                                   |
| 1    | no gap ends and no braced body starts on that line                                        |
| 2    | a usage error, a file that cannot be read or parsed, or a line beyond the end of the file |

For an `a.ts` file with two lines, `stanza explain a.ts:99` prints this on stderr and exits 2:

```text title="Beyond End of File"
stanza: a.ts has 2 lines, not 99
```
