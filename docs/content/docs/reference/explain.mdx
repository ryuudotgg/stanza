---
title: Explain
description: Ask which rule decides a line, and why.
---

```
stanza explain [--no-braces] [--] <file>:<line>[:<col>]
```

`stanza explain` explains the gap that ends at a line, the braced body that starts there and any wall that runs through it. It changes nothing.

Each section quotes the source lines it is about, and an answer quotes each line once: a section on a line an earlier section already quoted leaves that row out.

The location can carry a column, so the `path:line:col` a finding prints pastes as it is: `stanza explain src/load.ts:5:3` prints what `stanza explain src/load.ts:5` prints. The column selects nothing, and explain still covers the whole line. A location of the form `<a>:<n>:<m>`, with `n` and `m` digits, always reads as file `<a>`, line `n` and column `m`.

## A Gap

For a gap it prints the two statements, the rule that decided, what it found (the name a declaration binds and the statement that reads it, a guard, a statement spanning several lines), the rules it outranked and what `--fix` would do.

When either statement is a braceless two line `if`, `for` or `while`, or a braceless `if` with `else`, it also prints `width:`. This names the width in columns, its config or default source, and the joined length of each such statement. The line says whether it fits on one line. For an `if` with `else` it names the number of arms and the joined length of the widest, and says whether each arm fits on its own line.

When `--fix` removes braces inside either statement, or inside any statement of a block that holds 2 or 3 statements, where [short-body](/rules/short-body) judges them all, it prints a `note:` naming the lines of those braces as written.

  ../../../../tests/fixtures/after-multiline/example.before.ts
</include>

`stanza explain src/load.ts:5` prints:

```text title="Output"
src/load.ts:5

gap above line 5, no blank lines
  2-4      const raw = JSON.parse(
  5        if (!isRecord(raw)) throw new Error("config must be an object");
rule:      after-multiline, wants a blank line
because:   the statement above spans lines 2 to 4
outranked: guard-join, wants no blank line: `raw` is bound on line 2 and read by the `if` below it
result:    --fix adds a blank line
```

## A Braced Body

For a single statement body it says whether `--fix` removes the braces or why they stay:

- code after the body could continue the statement,
- a comment sits inside the braces,
- `--no-braces` was given,
- or a lint config file enforces braces, named in the output (see [Braces and Lint Config](/rules/braces-and-lint-config)).

## A Wall

For any line of a [wall](/rules/wall), from the comment above its first statement to the end of its last, it prints the run's first and last statements (one line when the whole run sits on it), how many statements run together and how many make a wall. `--fix` never splits a wall, so the result leaves the split to you. A run counts statements as `--fix` leaves them, so a blank line `--fix` removes does not split it, and a statement that is one line only once `--fix` removes its braces counts, with a `note:` naming those braces. The wall comes after any gap or braced body section on the same line, and a line inside two walls prints both.

Given this file at `src/boot.ts`:

<include lang="ts" meta='title="src/boot.ts" lineNumbers'>
  ../../../../tests/fixtures/wall/example.before.ts
</include>

`stanza explain src/boot.ts:2` prints:

```text title="Wall Output"
src/boot.ts:2

wall, lines 2 to 8
  2        const config = loadConfig(options.configPath);
  8        logger.info(`listening on ${config.port}`);
rule:      wall, wants a blank line where one step ends
because:   7 single-line statements run with no blank line --fix keeps, and 6 or more make a wall
result:    --fix leaves the split to you
```

## Options

It takes only `--no-braces`. It explains a file even when `--fix` and `--check` would skip it as generated or excluded, and ends with a note saying they skip it. For a file the [stanza attribute](/reference/file-selection#opting-a-file-out) opts out, the note names the attribute.

Use `--` before a path that starts with `-`, such as `stanza explain -- -draft.ts:5`. Flags must come before `--`. Arguments after the first `--` are literal, including `--no-braces` and any further `--`. Exactly one `<file>:<line>[:<col>]` location is required. Any path the shell passes is accepted, one holding a newline included, and the header prints a name holding a control character, a line or paragraph separator, `"` or `\` quoted as a [finding row](/reference/output#findings) quotes it.

## Exit Status

| exit | meaning                                                                                                                                                                                                  |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | something was explained                                                                                                                                                                                  |
| 1    | no gap ends, no braced body starts and no wall runs through that line                                                                                                                                    |
| 2    | a usage error, a path that is not a regular file, a file that cannot be read or parsed, a line beyond the end of the file, a working directory stanza cannot read, or an explanation stanza cannot write |

For an `a.ts` file with two lines, `stanza explain a.ts:99` prints this on stderr and exits 2:

```text title="Beyond End of File"
stanza: a.ts has 2 lines, not 99
```
