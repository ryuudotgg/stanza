```
stanza hook [--braces | --no-braces] [--hunks]
```

`stanza hook` is the PostToolUse hook on Write, Edit and MultiEdit for Claude Code and on `apply_patch` for Codex, the Stop hook for both, and the SubagentStop hook for both, which checks only the files the subagent wrote. This page is what it does with each input. What to write where is under [Claude Code](/agents/claude-code) and [Codex](/agents/codex).

It takes `--braces`, `--no-braces` and `--hunks` in its command, and they mean what they mean for [`--fix`](/reference/cli#flags). With `AGENT_HOOKS=0` in its environment it prints nothing and exits 0 before reading anything. That holds through the npm `stanza` command too, even when it has no binary to start.

## Input

The input is one JSON object on stdin, in UTF-8. Other fields are ignored. A string holding an unpaired surrogate escape such as `\ud800` names no file: a tool path, patch, transcript entry or rollout change holding one is skipped, and a `cwd`, `transcript_path`, `agent_transcript_path` or `hook_event_name` holding one is bad input, as is such an escape in a key of the input itself. A transcript or rollout line that is not valid UTF-8 names no file either, though a failed call it records still counts as failed, and neither it nor a record whose keys hold such an escape makes the Stop pass fall back to repository changes.

## Events

| `hook_event_name` | what runs                            |
| ----------------- | ------------------------------------ |
| absent, `Stop`    | the [Stop pass](#stop)               |
| `SubagentStop`    | the [subagent pass](#subagentstop)   |
| `PostToolUse`     | [fix the written file](#posttooluse) |
| anything else     | nothing, exit 0                      |

## Stop

The Stop pass runs one `--fix` pass over the files the agent wrote, or over changed files, picked as [`--changed`](/reference/file-selection#changed-files) picks them.

With a readable Claude Code transcript at `transcript_path`, it keeps only the files the agent created or edited with Write, Edit or MultiEdit, so files a human left dirty stay untouched. A tool call that failed does not count. It also reads every `.jsonl` transcript at any depth below the session's `subagents` folder (the transcript path without `.jsonl`, then `subagents`), so Task subagents and Workflow agents count too. It does not follow a directory symlink there, and a missing or malformed transcript adds nothing. Every Stop reads all of these transcripts, so a session with many agents takes longer to check. With a Codex rollout, it keeps files that completed patches added, updated or moved to, so a rollout with no completed patch changes no file and prints nothing. Those files are fixed in whichever repository holds them, which need not be the one at `cwd`, except a path whose symlink leads out of its repository. When git fails in one of those repositories, the hook writes the failure on stderr, still fixes and reports the files in the others, then exits 1. Without a transcript, or with one Stanza does not recognise, it takes every changed file in the repository at `cwd`, including ones edited by hand.

A file the agent wrote is checked whether or not it differs from HEAD, so committing it before the turn ends does not hide a finding. The transcript covers the whole session, so every later Stop checks that path again, whatever it holds by then: after a branch switch or a commit by someone else, it checks their content. Besides the files any selection skips, a written file is skipped when it no longer exists, or when git ignores it and does not track it. With `--hunks`, only lines that differ from HEAD are in scope: a written file with no diff against HEAD is not checked, and an untracked one counts as changed throughout.

It prints nothing when:

- the files come out clean,
- `stop_hook_active` is true,
- no file it would fix is inside a git repository,
- `cwd` does not exist and no transcript Stanza can read names the files.

When findings remain that `--fix` cannot apply, it prints a block decision on stdout:

```json
{ "decision": "block", "reason": "..." }
```

The reason is plain text. It opens with what the agent has to do, then lists the findings by file, files in byte order and findings by line, each as `line N: message (rule)`. After twelve findings the list stops with a count of the rest. When the pass rewrote any file, a line then names every file it rewrote, so the agent reads them again before editing. The last line asks the agent to fix the findings and reply again, pointing to [`stanza explain`](/reference/explain). A path holding a control character, a line or paragraph separator, `"` or `\` prints quoted, as in a [finding row](/reference/output).

After a pass that rewrote `src/orders.ts` and left findings it cannot fix in `src/report.ts` and `src/users.ts`, the reason reads:

```text title="Reason"
These need a hand fix in the files you changed:

src/report.ts
  line 2: split these 8 statements into steps with a blank line (wall)
  line 10: add a blank line above this block, or join it to the step above (block-spacing)

src/users.ts
  line 4: split these 7 statements into steps with a blank line (wall)

stanza rewrote src/orders.ts, so read it again before editing.
Fix the findings above, then reply again. `stanza explain <file>:<line>` shows why a rule applies.
```

A file that fails is listed like any finding, with `parse`, `write` or `error` as its rule, such as `line 1: Unexpected token (parse)`, and the rest of the pass still runs.

A file stanza hits an internal error on is left untouched and listed with an `error` finding, `internal error (...), left untouched`. The rest of the pass still runs, then the hook writes one line on stderr naming the file and exits 1, so Claude Code shows a notice rather than blocking the agent on a bug in stanza.

## SubagentStop

SubagentStop runs the same fix and block pass as Stop, but only over files its own `agent_transcript_path` names. As in Stop, each of them is checked whether or not it differs from HEAD, except under `--hunks`, which skips a file with no diff against HEAD. It counts absolute paths from Write, Edit and MultiEdit calls, excluding failed calls, or, in a Codex rollout, files that completed patches added, updated or moved to. It ignores `transcript_path` and never discovers sibling or descendant transcripts.

It prints nothing, changes no file and exits 0 when `agent_transcript_path` is absent, unreadable, unrecognised or names no writes. It never falls back to repository changes. A clean pass or `stop_hook_active: true` also prints nothing. Remaining findings block only on the subagent's own files, using the same decision and reason as Stop.

## PostToolUse

After a Write, Edit or MultiEdit, it runs one `--fix` pass over `tool_input.file_path`. After an `apply_patch`, it runs one over the paths the patch's `*** Add File:`, `*** Update File:` and `*** Move to:` lines name. A relative path is joined to [`cwd`](#input) as the tool joins it, and a `*** Delete File:` path writes nothing. Files are picked as in the [Stop pass](#stop), kept to the ones the call wrote, and `--hunks` narrows the fixes the same way: a Write to a file tracked in HEAD has only its diff against HEAD fixed. The permission prompt and the Write result show the text as the agent sent it.

When it changes a file, it prints on stdout:

| field                                  | value                                                |
| -------------------------------------- | ---------------------------------------------------- |
| `hookSpecificOutput.hookEventName`     | `PostToolUse`                                        |
| `hookSpecificOutput.additionalContext` | names each file it changed and asks for a fresh read |

It prints nothing when:

- nothing changes,
- `tool_response` has no success line (Codex 0.159 fires no PostToolUse for a failed patch at all),
- a file does not parse,
- a file is not TypeScript or JavaScript, is [always skipped](/reference/file-selection#always-skipped), [generated](/reference/file-selection#generated-files) or ignored by git,
- a file is outside git, or a symlink leads it out of its repository,
- `cwd` does not exist and a file's path is relative.

Findings `--fix` cannot apply are left for the Stop pass to report.

## Exit Status

| exit | when                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | effect in Claude Code      |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 0    | every run that did not fail, whether or not it printed anything                                                                                                                                                                                                                                                                                                                                                                                                                                | none                       |
| 1    | bad input, input that is not valid UTF-8, a flag other than `--braces`, `--no-braces` or `--hunks`, both braces flags, a git failure while picking files (the other repositories are still fixed and reported), a changed file whose name is not valid UTF-8, a relative or missing `cwd`, or a relative `transcript_path` or `agent_transcript_path` the event reads, when stanza cannot read the process working directory, an internal error, or a reply on stdout that stanza cannot write | a notice, without blocking |

The message goes to stderr. It never exits 2: a Stop hook that exits 2 blocks the agent, and a PostToolUse hook that exits 2 replaces the tool result.
