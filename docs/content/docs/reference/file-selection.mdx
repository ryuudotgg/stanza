A run takes its files from exactly one source: paths, `--changed`, `--staged`, or a single buffer on `--stdin`. Whatever the source, the [always skipped](#always-skipped) list and [generated file detection](#generated-files) apply.

Stanza formats `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs` and `.cjs` files.

## Paths

`stanza --fix <paths...>` and `stanza --check <paths...>` take files and directories. Directories recurse. Put `--` before paths that start with `-`.

A path names the file the system opens for it, as `cat` does. A `..` after a symlinked folder steps up from where the link leads, so with `link` pointing at `real/inner`, `link/../a.ts` is `real/a.ts`. The same holds for an `explain` target and for the folders of a `--stdin` path that exist.

| where the path is           | how its files are listed                                                        |
| --------------------------- | ------------------------------------------------------------------------------- |
| inside a git work tree      | `git ls-files`, tracked and untracked, so `.gitignore` applies exactly          |
| outside git                 | a directory walk that applies every `.gitignore` in it with git's pattern rules |
| anywhere, git not on `PATH` | the directory walk, with a warning on stderr                                    |

When the walk outside git reaches a repository, it hands that folder to git as if you had named it, so the repository's own ignore rules and attributes decide its files. A `.gitignore` above the repository can still skip the whole folder, but its rules for files inside it do not apply.

The walk starts from where a folder argument leads, as a repository listing does. A symlinked folder and its target select each file once, under the target's name, and the `.gitignore` files above the target apply. Symlinked folders the walk finds inside are not followed.

A file named directly is taken even when a `.gitignore` lists it. The always skipped list and generated file detection still apply to it.

| path                                                                  | result                                                   |
| --------------------------------------------------------------------- | -------------------------------------------------------- |
| does not exist                                                        | error, exit 2                                            |
| a file that is not TypeScript or JavaScript                           | error, exit 2                                            |
| a directory or `.gitignore` it cannot read, or a path it cannot reach | `stanza: cannot read <path>: <reason>` on stderr, exit 2 |
| a FIFO, socket or device file                                         | `stanza: not a regular file: <path>` on stderr, exit 2   |
| a name that is not valid UTF-8                                        | [reported](#names-that-are-not-utf-8), exit 2            |
| selects nothing                                                       | one line on stderr saying why, exit 0                    |

For a folder `locked` that the run cannot open, stderr reads:

```text title="Unreadable Folder"
stanza: cannot read locked: permission denied
```

For a FIFO named `pipe.ts`:

```text title="Not a Regular File"
stanza: not a regular file: pipe.ts
```

The line for an empty selection names the reason for each path: the stanza attribute opts its files out, every file under it is generated, git ignores its files, its files are always skipped, or it holds no TypeScript or JavaScript files. Paths with the same reason share one line. For `stanza --check a.gen.ts ignored`, with `ignored` in `.gitignore`, stderr reads:

```text title="Empty Selection"
stanza: nothing to format in a.gen.ts, generated files are skipped
stanza: nothing to format in ignored, git ignores its files
```

When a path holds a git repository that the outer repository does not track, an empty run names that repository on its own line, since its files belong to it, and the reason for the path covers only the outer repository's files. A folder whose only content is such a repository gets the repository line alone:

```text title="Nested Repository"
stanza: skipped nested git repository inner, pass its path to format its files
```

### Submodules

Files inside a git submodule belong to the submodule's own repository, so a path in the superproject leaves them out, and stderr gives one line for each submodule it skipped:

```text title="Skipped Submodule"
stanza: skipped git submodule vendor/sub, pass its path to format its files
```

Naming the submodule, or a path inside it, formats its files. `--changed` and `--staged` print the same line when the submodule has changes or a staged new commit. The hook prints nothing for a submodule.

## Always Skipped

| kind                | skipped                                                                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| declaration files   | `*.d.ts`, `*.d.mts`, `*.d.cts`                                                                                                                              |
| generated by name   | `*.gen.ts`, `*.gen.tsx`, `*.gen.mts`, `*.gen.cts`, `*.gen.js`, `*.gen.jsx`, `*.gen.mjs`, `*.gen.cjs`, `*.generated.*`, `*.min.js`, `*.min.mjs`, `*.min.cjs` |
| directories         | `node_modules`, `dist`, `build`, `.next`, `out`, `coverage`, `migrations`, `drizzle`, unless the `stanza` attribute is set, see [below](#opting-a-file-in)  |
| git attributes      | files marked `linguist-generated` in `.gitattributes`                                                                                                       |
| stanza attribute    | files whose `stanza` git attribute is unset or false, written `-stanza` or `stanza=false` in `.gitattributes`, see [below](#opting-a-file-out)              |
| generated by header | files whose first ten lines hold a comment that marks them as generated, see [below](#generated-files)                                                      |

Inside a git repository the skipped directory names count from the repository root, whatever path you pass and wherever you run. `stanza --check dist`, or `stanza --check .` run inside `dist`, skips what `stanza --check dist/a.ts` skips. A repository kept inside a folder such as `build` counts from its own root, so its files are still formatted. Outside git the names count from the path you pass: `stanza --check build/project` formats `build/project/keep.ts` and skips `build/project/dist`, while `stanza --check build/project/dist` formats the files in it.

## Generated Files

A comment in the first ten lines marks a file as generated when it says so outright:

- `@generated`
- `Code generated by protoc. DO NOT EDIT.`, or any comment that starts `Code generated` and says do not edit
- `This file was automatically generated`, and the same with `is`, `has been`, `code` or `class`
- `auto-generated file`, `autogenerated code` and the like

A `Generated by` (or `from`, `with`, `using`) line counts only when a comment in those ten lines warns not to edit the file. The warning can sit in the same comment as the line, as in `// Generated by tool. DO NOT EDIT.`, or in a separate comment. A comment that only says `do not edit` is not enough on its own.

[`stanza explain`](/reference/explain) still explains a generated or skipped file, and says that `--fix` and `--check` skip it.

## Opting a File Out

To keep stanza off a file without editing it, unset its `stanza` git attribute:

```
# .gitattributes
packages/shared/src/pinned.ts -stanza
legacy/** stanza=false
```

No source takes the file, not paths, `--changed`, `--staged`, `--stdin` or the hook, and it is never reported as generated. Stanza reads the attribute through git, so `.gitattributes`, `.git/info/attributes` and the global and system attributes files all count. With no git on `PATH` the directory walk reads no attributes, so the opt out needs git, as `linguist-generated` does. Setting it lifts the skipped directory rule for a file, as [below](#opting-a-file-in), and any other value leaves the file as it was. Unlike a `stanza-off` comment, the file itself stays untouched.

[`stanza explain`](/reference/explain) still explains an opted out file, and says the attribute is why `--fix` and `--check` skip it.

## Opting a File In

Inside a git repository, setting a file's `stanza` attribute lifts the skipped directory rule for it, so source kept in a folder named `dist`, `build` or another directory on the list still gets formatted:

```
# .gitattributes
dist/** stanza
packages/cli/build/*.ts stanza=true
```

Every source takes the file: paths, `--changed`, `--staged`, `--stdin` and the hook. Only the directory rule lifts. Declaration files, generated names, `linguist-generated` and a generated header still skip it, and a directory, `--changed` or `--staged` still leaves out what git ignores. `--staged` takes the file only when the index and the working tree both set it, since `--fix` reads the working tree. Outside a repository, or with no git on `PATH`, no attribute is read and the directory list applies as before.

## Changed Files

```
stanza --fix --changed
stanza --check --changed --hunks
```

`--changed` takes the files from `git diff --name-only HEAD` plus untracked files, across the whole repository whatever the working directory. Before the first commit it takes every tracked and untracked file. Outside a git repository, or with no git on `PATH`, it is an error and exits 2. A changed file under a directory stanza cannot search, an untracked directory git cannot open, or a `.gitignore` git cannot read, prints the `cannot read` line a path run prints and exits 2, while a file deleted from the working tree is skipped without a word.

## Hunks

`--hunks` narrows `--changed` or `--staged` to the lines changed against HEAD.

| part of the code                                                    | when a rule applies under `--hunks`                                                                  |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| a gap between two statements                                        | one of the two statements around it, or a blank line between them, is on a changed line              |
| a braced body                                                       | the block holds a changed line, or sits next to such a gap                                           |
| a braced body in a block [short-body](/rules/short-body) could join | also when any gap of that block applies, judging each statement as it reads once its braces come off |
| an untracked file                                                   | always, the whole file counts as changed                                                             |
| a file with a `filter` attribute                                    | always, the whole file counts as changed, since git diffs its cleaned text                           |

A gap is touched when the first row applies to it. In a block of 2 or 3 statements that are compact after brace removal, a touched gap puts every statement in scope, even when the gap has no blank line. This widening does not apply at module top level or beside a statement that cannot be compact. [short-body](/rules/short-body#compact) defines compact.

What counts as a changed line:

- Braces stanza removed do not make a line changed, so a second run changes nothing.
- A deleted line that held only a brace is no change at all.
- Any other deleted line counts only for the gap it sat in.

For holding new changes to the rules in a codebase that does not follow them yet, see [Existing Codebases](/guides/existing-codebases).

## Staged

```
stanza --check --staged
stanza --check --staged --hunks
```

`--staged` checks what is in the index, not the working tree. It picks files by the same rules as `--changed`, and reads `.gitattributes` from the index too. A file the `stanza` attribute opts out in either the index or the working tree is skipped, since `--fix` would skip it. Lint config still comes from each file's real path. It works only with `--check`.

With `--hunks` it narrows to the lines the index changes against HEAD. Before the first commit every staged line counts. A staged file with a `filter` attribute counts as changed throughout, since its index blob is not the text being checked. A filtered blob is converted with the attributes the index holds, so an unstaged `.gitattributes` edit does not change the text checked. A staged file whose `filter`, `working-tree-encoding`, `text`, `eol`, `crlf` or `ident` differs between the index and the working tree needs git 2.40 or later.

When findings `--fix` can apply remain, stderr ends, after the [summary](/reference/output#summary), with what to do about each file:

| staged file                                         | what stderr says                                                     |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| no unstaged changes, whole file in scope            | one command that fixes these files and stages them again             |
| also has unstaged changes                           | listed on its own line, to fix with `--fix` and restage by hand      |
| under `--hunks`, scope narrower than the whole file | listed on its own line, to fix by hand and restage with `git add -p` |

So no unstaged work gets staged, and `--fix`, which has no staged line scope, never rewrites lines outside the check. For running this as a hook, see [Pre-Commit Hook](/guides/pre-commit).

## Names That Are Not UTF-8

Linux lets a file or directory name hold bytes that are not valid UTF-8. Stanza cannot read such a name as a path, so a TypeScript or JavaScript file under one is reported, quoted as git quotes it, and left untouched:

```
stanza: name is not valid UTF-8: "src/bad\377.ts"
```

A path argument, a directory, `--changed`, `--staged` and a symlink leading to such a name all print the line and exit 2, and the rest of the run still goes ahead. `--staged` leaves the file out of the command it suggests. The `stanza` attribute and `linguist-generated` skip such a file as they skip any other. The hook prints the line after `stanza hook:` and exits 1, without blocking. A working directory with such a name is treated as one stanza cannot read, so a run that needs it exits 2. A file whose name ends in another extension is skipped as before. macOS refuses these names, so there is nothing to report there.

## JSX

`.tsx`, `.jsx`, `.js`, `.mjs` and `.cjs` files can hold JSX.

Stanza leaves JSX markup as written: tags, attributes, text and the lines between them. The code inside it, such as an `onClick` callback, a function passed to `map` in children or a render prop, gets every rule a `.ts` or `.js` file gets. A `{/* stanza-off */}` comment inside markup leaves the code below it alone up to a `{/* stanza-on */}`. A `stanza-ignore` needs a statement directly below it, so it goes inside the callback, above that statement.
