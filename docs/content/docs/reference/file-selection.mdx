title: File Selection
description: See which files a run takes, and which it always skips.
---

A run takes its files from exactly one source: paths, `--changed`, `--staged`, or a single buffer on `--stdin`. Whatever the source, the [always skipped](#always-skipped) list and [generated file detection](#generated-files) apply.

Stanza formats `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs` and `.cjs` files.

## Paths

`stanza --fix <paths...>` and `stanza --check <paths...>` take files and directories. Directories recurse. Put `--` before paths that start with `-`.

| where the path is           | how its files are listed                                                        |
| --------------------------- | ------------------------------------------------------------------------------- |
| inside a git work tree      | `git ls-files`, tracked and untracked, so `.gitignore` applies exactly          |
| outside git                 | a directory walk that applies every `.gitignore` in it with git's pattern rules |
| anywhere, git not on `PATH` | the directory walk, with a warning on stderr                                    |

A file named directly is taken even when a `.gitignore` lists it. The always skipped list and generated file detection still apply to it.

| path                                        | result                                |
| ------------------------------------------- | ------------------------------------- |
| does not exist                              | error, exit 2                         |
| a file that is not TypeScript or JavaScript | error, exit 2                         |
| selects nothing                             | one line on stderr saying why, exit 0 |

The line for an empty selection names the reason: every file under it is generated, git ignores its files, its files are always skipped, or it holds no TypeScript or JavaScript files.

## Always Skipped

| kind                | skipped                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------ |
| declaration files   | `*.d.ts`, `*.d.mts`, `*.d.cts`                                                                         |
| generated by name   | `*.gen.ts`, `*.gen.tsx`, `*.generated.*`, `*.min.js`                                                   |
| directories         | `node_modules`, `dist`, `build`, `.next`, `out`, `coverage`, `migrations`, `drizzle`                   |
| git attributes      | files marked `linguist-generated` in `.gitattributes`                                                  |
| generated by header | files whose first ten lines hold a comment that marks them as generated, see [below](#generated-files) |

## Generated Files

A comment in the first ten lines marks a file as generated when it says so outright:

- `@generated`
- `Code generated by protoc. DO NOT EDIT.`, or any comment that starts `Code generated` and says do not edit
- `This file was automatically generated`, and the same with `is`, `has been`, `code` or `class`
- `auto-generated file`, `autogenerated code` and the like

A `Generated by` (or `from`, `with`, `using`) line counts only when another comment in those ten lines warns not to edit the file. A comment that only says `do not edit` is not enough on its own.

[`stanza explain`](/reference/explain) still explains a generated or skipped file, and says that `--fix` and `--check` skip it.

## Changed Files

```
stanza --fix --changed
stanza --check --changed --hunks
```

`--changed` takes the files from `git diff --name-only HEAD` plus untracked files, across the whole repository whatever the working directory. Before the first commit it takes every tracked and untracked file. Outside a git repository, or with no git on `PATH`, it is an error and exits 2.

## Hunks

`--hunks` narrows `--changed` or `--staged` to the lines changed against HEAD.

| part of the code             | when a rule applies under `--hunks`                                                     |
| ---------------------------- | --------------------------------------------------------------------------------------- |
| a gap between two statements | one of the two statements around it, or a blank line between them, is on a changed line |
| a braced body                | the block holds a changed line, or sits next to such a gap                              |
| an untracked file            | always, the whole file counts as changed                                                |

What counts as a changed line:

- Braces stanza removed do not make a line changed, so a second run changes nothing.
- A deleted line that held only a brace is no change at all.
- Any other deleted line counts only for the gap it sat in.

For holding new changes to the rules in a codebase that does not follow them yet, see [Existing Codebases](/guides/existing-codebases).

## Staged

```
stanza --check --staged
stanza --check --staged --hunks
```

`--staged` checks what is in the index, not the working tree. It picks files by the same rules as `--changed`, and reads `.gitattributes` from the index too. Lint config still comes from each file's real path. It works only with `--check`.

With `--hunks` it narrows to the lines the index changes against HEAD. Before the first commit every staged line counts. A staged file with a `filter` attribute counts as changed throughout, since its index blob is not the text being checked. A staged file whose `filter` differs between the index and the working tree needs git 2.40 or later.

When findings `--fix` can apply remain, stderr ends with what to do about each file:

| staged file                                         | what stderr says                                                     |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| no unstaged changes, whole file in scope            | one command that fixes these files and stages them again             |
| also has unstaged changes                           | listed on its own line, to fix with `--fix` and restage by hand      |
| under `--hunks`, scope narrower than the whole file | listed on its own line, to fix by hand and restage with `git add -p` |

So no unstaged work gets staged, and `--fix`, which has no staged line scope, never rewrites lines outside the check. For running this as a hook, see [Pre-Commit Hook](/guides/pre-commit).
