## 0.5.0

_November 19, 2026_

### 🚨 Heads up

- **Files are listed in byte order, as git lists them** ([#264](https://github.com/ryuudotgg/stanza/pull/264))\
  Findings, `--json` output, error lines, the `--staged` repair lines, the hook's lists of files and the notices that name config files now order paths by their bytes, the order `git ls-files` and `LC_ALL=C sort` use, so `Button.ts` and `_x.ts` come before `api.ts`. A script that reads `--json` findings in order sees the new order. Errors from several path arguments sort by path, so `stanza --check z a` reports a missing `a` before an unreadable `z`, and two files whose names differ only by an invisible character no longer have their findings mixed together.
- **Findings say what to change** ([#266](https://github.com/ryuudotgg/stanza/pull/266))\
  Every rule's finding message now starts with the change to make, such as `add a blank line after the multi-line statement above` or `remove the braces around this single statement body`, and a wall names its length, as in `split these 8 statements into steps with a blank line`. The new words show in the finding rows, in `--json` and in the hook's block reason, so a script that matches the old messages must change.
- **Finding rows separate their fields with colons** ([#301](https://github.com/ryuudotgg/stanza/pull/301))\
  `--check` and `--fix` now print each finding as `path:line:col: rule: message`, and a finding `--fix` leaves for you ends with ` (by hand)`. A path holding a control character, a line or paragraph separator, `"` or `\` prints quoted, in the escapes `git status` uses, such as `"a\nb.ts"`, so every finding stays on one line and no file name can restyle the terminal. `--fix --stdin` prints the same rows on stderr, and `--json` is unchanged, so a script that parses the old rows must change, or read `--json` instead.
- **Override patterns the formatters read differently leave their config unread** ([#336](https://github.com/ryuudotgg/stanza/pull/336))\
  When an oxfmt, Prettier or Biome config holds an override or include pattern whose meaning differs between the formatters, Stanza now names that config in the unread notice and takes the width from the next source, even when the pattern's override does not cover the file. That covers extglobs such as `@(a|b).ts`, ranges such as `{1..3}.ts`, braces with one choice such as `{src}/**`, nested braces, a `/` or `**` inside braces such as `{src/**,lib/**}`, negated or POSIX classes such as `[!a]` and `[[:alpha:]]`, `**` inside a name such as `**.ts`, a `+` after a class or braces such as `[ab]+.ts`, a backslash or double quote, and a leading `!` in a Prettier or oxfmt pattern. A Biome pattern with `?` or a class does the same, since Biome rejects it. Write `{src/**,lib/**}` as `{src,lib}/**` to keep the config's width. A leading `!` in a Biome include list still excludes what it names.
- **The hook registrations add SubagentStop** ([#441](https://github.com/ryuudotgg/stanza/pull/441))\
  The Claude Code and Codex registrations in `stanza --help`, the README and the setup pages now add a SubagentStop entry beside PostToolUse and Stop, so each subagent's own files are fixed when it finishes instead of waiting for the end of the turn. A registration copied from an earlier release has no SubagentStop entry: add the one from `stanza --help`, and in Codex trust it again with `/hooks`, since Codex skips a new or edited hook until you do.
- **Claude Code Writes are fixed after they land** ([#429](https://github.com/ryuudotgg/stanza/pull/429))\
  `stanza hook` now fixes a Write on PostToolUse, as it does an Edit and MultiEdit, so register it once with the matcher `Write|Edit|MultiEdit` and drop the PreToolUse entry for Write. A PreToolUse event now prints nothing, so a registration copied from an earlier release leaves each Write unformatted until the Stop pass: replace it with the one in the README. The permission prompt and the Write result show the text as the agent sent it, and the agent is told to read the file again when Stanza changed it. Under `--hunks`, a Write to a file tracked in HEAD now has its changed lines fixed instead of waiting for the Stop pass.

### ✨ New

- **Runs end with a summary line** ([#333](https://github.com/ryuudotgg/stanza/pull/333))\
  `--check` and `--fix` over paths, `--changed` or `--staged` now end with one line on stderr that counts what the run found and did, such as `4 findings in 2 files: 2 fixable with --fix, 2 by hand`, `checked 12 files, no findings` or `rewrote 2 files, no findings left`, and a file that failed adds a clause such as `, 1 file failed`. A `--changed` or `--staged` run that selects nothing now says `no changed files to check` or `no staged files to check` instead of printing nothing. Under `--staged` the repair lines now come last, after the lines about names that are not UTF-8, the config notices and the summary. `--json`, `--stdin`, `stanza explain` and the hook print no summary, and the exit code is unchanged.
- **A terminal shows aligned, colored findings** ([#353](https://github.com/ryuudotgg/stanza/pull/353))\
  When stdout is a terminal, `--check` and `--fix` over paths, `--changed` or `--staged` line up each file's findings in columns, with a blank line between files and before the summary. The location prints bold, the rule dim and `(by hand)` yellow. When stderr is a terminal, the `stanza:` prefix prints bold red on an error and bold yellow on a notice, and the summary's numbers print bold. `NO_COLOR` and `TERM=dumb` turn color off, and `FORCE_COLOR` colors piped output in the one finding per line form, though never the stdout of `--json`, `--stdin`, `stanza explain`, `--help` or the hook. Under a coding agent that sets `CLAUDECODE`, `AI_AGENT`, `CODEX_SANDBOX`, `CODEX_THREAD_ID`, `CURSOR_AGENT` or `GEMINI_CLI`, the output keeps one finding per line with no color, as it does in a pipe.
- **Explain takes a finding's location as printed** ([#386](https://github.com/ryuudotgg/stanza/pull/386))\
  `stanza explain` now accepts the `path:line:col` a finding row prints, so `stanza explain src/orders.ts:6:3` explains the same line as `stanza explain src/orders.ts:6`; the column changes nothing. Paths holding a newline or a line separator are accepted too, and the header and every error line quote such a name as a finding row does, as do the `--stdin` and hook lines that name an unsupported or unreadable path. A line past the end of the file is named as it was typed, however many digits it has.
- **Explain shows the wall a line runs through** ([#406](https://github.com/ryuudotgg/stanza/pull/406))\
  `stanza explain` on any line of a wall now prints a wall section: the run's lines, its first and last statements, how many statements run together and that 6 or more make a wall, and that `--fix` leaves the split to you. It counts the run as `--check` does, after `--fix` removes braces and the blank lines its rules drop. A line with no gap, braced body or wall still exits 1.
- **The stanza attribute opts files in skipped folders back in** ([#403](https://github.com/ryuudotgg/stanza/pull/403))\
  Setting the `stanza` git attribute on a file, such as `dist/** stanza` in `.gitattributes`, now lets every source take it even though it sits below an always skipped folder like `dist`, `build` or `node_modules`. Paths, `--changed`, `--staged`, `--stdin` and the hook all format it, while declaration files, generated names, `linguist-generated` and generated headers still skip it. Before, setting the attribute changed nothing.
- **`stanza --help` prints the Codex registration** ([#441](https://github.com/ryuudotgg/stanza/pull/441))\
  `stanza --help` now prints the registration for `~/.codex/hooks.json` or `.codex/hooks.json` below the Claude Code one, so both can be copied without opening the docs.

### 🎨 Improved

- **The binary is about 500 KB smaller and a little faster** ([#219](https://github.com/ryuudotgg/stanza/pull/219))\
  The `stanza` binary in each platform package is now built with whole program optimisation and without a regular expression parser it never used, so it downloads less and a serial `--check` runs about 5% fewer instructions. Every finding and fix is unchanged.
- **Long `else if` chains and long `let` runs check faster** ([#220](https://github.com/ryuudotgg/stanza/pull/220))\
  Stanza does less work per statement, so a whole repository check runs about 5% fewer instructions. An unbraced `else if` chain, and a long run of `let` declarations read by the statement after it, now take time that grows with their length rather than its square: 8000 of either goes from one to three and a half billion instructions down to about a tenth of a billion. What Stanza reports and fixes stays the same.
- **Long lines with many findings report faster** ([#214](https://github.com/ryuudotgg/stanza/pull/214))\
  Columns are now worked out in one pass over each line, so a file whose findings crowd onto one long line, such as bundled or minified code, no longer slows down with every finding added. A one line file with 4000 findings drops from about a third of a second to a few milliseconds in `--check`, and every finding keeps the line and column it had before.
- **Blank line fixes finish sooner** ([#210](https://github.com/ryuudotgg/stanza/pull/210))\
  `--fix` no longer parses a file a second time when the fix only adds or removes blank lines, so fixing a repository full of spacing findings spends about a quarter less time computing. `--hunks` runs still check the fixed text the way they did before.
- **The npm command starts the binary sooner** ([#199](https://github.com/ryuudotgg/stanza/pull/199))\
  `stanza` from a local, npx, npm global or Bun global install now reaches the platform binary without starting `readlink` or `uname`, so each run through `node_modules/.bin/stanza`, a hook included, starts a few milliseconds sooner on macOS on Apple silicon and on Linux.
- **`--hunks` keeps up with long changed lines** ([#205](https://github.com/ryuudotgg/stanza/pull/205))\
  `--hunks` now sorts each changed line into touched and untouched code in time that grows with the line's length, where a long line such as minified code used to take time growing with its square. Unchanged lines in a changed file are compared as written instead of being copied and hashed, so on a repository with 20 edited files the work `--hunks` adds on top of `--changed` drops by about three quarters. Which lines count as touched stays the same.
- **The binary is about 1.2 MB smaller** ([#215](https://github.com/ryuudotgg/stanza/pull/215))\
  The `stanza` binary now matches generated file headers, ignore directives and git warnings with a smaller pattern engine, so each platform package downloads less, and a file with no header comment no longer prepares the header patterns at all. Which files count as generated, and every directive, behave as before.
- **File selection starts fewer git processes and runs them together** ([#218](https://github.com/ryuudotgg/stanza/pull/218))\
  `--changed`, `--changed --hunks` and the hook after an edit or at the end of a turn run the git calls that pick changed files side by side instead of one after another, and a `Stop` does the same across the repositories it names. A repository that tracks a `.gitattributes` no longer makes every hook event, `--changed` run and directory run start `git check-attr`: Stanza skips it when no attribute source git would read can name `linguist-generated` or `stanza`. In a linked worktree or a submodule checkout, Stanza now finds the repository and rules out attributes from the files on disk, as it already did in a main checkout. When the git index shows that every file an edit or a turn's transcript names is already tracked, `stanza hook` no longer starts `git ls-files --others`, which can only list untracked files. `--staged` reads files with a clean or smudge `filter` through one `git cat-file --batch --filters`, so five filtered files start one git process where they used to start five. Files whose driver runs a `filter.<driver>.process`, and paths holding a newline, ending in a carriage return or starting with a space or tab, are still read one at a time. A check outside any repository usually learns that from the files on disk, so a file under `/tmp` starts no git process at all. Inside a repository, git lists a directory with nothing to format once instead of twice. The files picked and everything printed stay the same.
- **Large repositories read each config once** ([#221](https://github.com/ryuudotgg/stanza/pull/221))\
  A run that formats files on several threads now reads each ESLint, oxlint, Biome, Prettier and oxfmt config once and shares it, instead of once per thread. A repository whose `eslint.config.js` imports a 600 KB module checks in about 25 MB, where it took 790 MB with four threads and 1.1 GB with eight, and spends the CPU time of a single threaded run. Every file still gets the brace setting and line width it did before.
- **Stop hook reads long transcripts in far less memory** ([#200](https://github.com/ryuudotgg/stanza/pull/200))\
  The Stop and SubagentStop hooks now read the session transcript and each subagent transcript one line at a time, so a 366 MB transcript peaks at about 9 MB instead of over 700 MB. The files they pick and what they print stay the same.
- **Checks run faster, most of all on Alpine** ([#222](https://github.com/ryuudotgg/stanza/pull/222))\
  The `stanza` binary now allocates memory through mimalloc on every platform, for 40 to 60 KB more download. On Alpine and other musl systems a `--check` spread across worker threads no longer queues on the system allocator, so it runs about three times faster and keeps pace with the glibc build. On macOS a serial run takes 13 to 15% less time. Every finding and fix is unchanged.
- **Many file paths are selected as fast as their directory** ([#227](https://github.com/ryuudotgg/stanza/pull/227))\
  Stanza now resolves where a file really lives once per directory, not once per file and per parent folder. Passing 2000 files as arguments now costs about the same CPU as passing the one directory that holds them, where before it cost twice as much. Selecting a whole repository also uses less CPU. The files picked and everything printed stay the same.
- **Smaller binary** ([#239](https://github.com/ryuudotgg/stanza/pull/239))\
  JavaScript and TypeScript configs are now read straight from the parsed syntax tree instead of a JSON copy of it, so the `stanza` binary is about 210 KB smaller. Every brace setting, line width and notice is unchanged.
- **Runs use more worker threads on machines with more cores** ([#236](https://github.com/ryuudotgg/stanza/pull/236))\
  Without `STANZA_WORKERS`, a run of 64 files or more now uses one worker thread fewer than the available parallelism, up to eight, where before it waited for 256 files and used at most three. On an 18 core machine a 1454 file `--check` finishes about a fifth sooner, and every finding and fix is unchanged. `STANZA_WORKERS` keeps its range and still overrides the default at any file count.
- **Runs with many findings use less memory** ([#246](https://github.com/ryuudotgg/stanza/pull/246))\
  Stanza used to keep a copy of the file name on every finding and build the whole report before printing the first line. Findings now share their file's name and the report goes out in pieces as it is written, so a `--check` run with hundreds of thousands of findings needs about half the memory it did, with or without `--json`. The report itself is unchanged, byte for byte and in the same order.
- **The binary sheds its collation data** ([#264](https://github.com/ryuudotgg/stanza/pull/264))\
  The `stanza` binary no longer carries the Unicode collation code and data it sorted paths with, about 1.2 MB, so each platform package downloads less.
- **Failures name the system's reason in plain words** ([#267](https://github.com/ryuudotgg/stanza/pull/267))\
  When the system refuses a read, a write or a start, stanza now says why in the system's own words, as in `stanza: cannot read locked: permission denied` or the `parse` finding `cannot read: permission denied`, where it used to print a code such as `EACCES`, a `(os error 13)` suffix or nothing at all. The npm launcher does the same when it cannot start the binary, naming the platform package rather than its path, and `stanza explain` names the real reason it could not read a lint config. Only the words change: the same failures go to the same streams with the same exit codes and rule ids.
- **Notices and errors read plainly and name the program that printed them** ([#268](https://github.com/ryuudotgg/stanza/pull/268))\
  Lines on stderr now say `cannot` where they said `could not`, as in `stanza: cannot read the line width from .prettierrc.json, so the next source sets it`. `stanza hook` prints its brace and line width notices after `stanza hook:` instead of `stanza:`, and so does the npm launcher when it runs as `stanza hook`. A git failure names the folder git ran in relative to the working directory, or leaves it out when they are the same, and names the index as git does, such as `stanza: git diff failed: fatal: .git/index: index file smaller than expected`, where it used to print absolute paths and a temporary copy of the index. The same failures go to the same streams with the same exit codes.
- **The npm page describes Stanza as the README does** ([#269](https://github.com/ryuudotgg/stanza/pull/269))\
  The `@ryuugg/stanza` package description on npm now reads `An opinionated formatter for turning function bodies into readable steps.`, the same line the README and the docs open with. It used to say `An opinionated code formatter for TypeScript.`, which left out JavaScript.
- **One file costs the same in a crowded folder** ([#303](https://github.com/ryuudotgg/stanza/pull/303))\
  Checking one named file, or one file read with `--stdin`, no longer reads a crowded folder in full, or the crowded folders above it, to find config files. Beside 50,000 other files, `stanza --check` on one file used about 20 times the CPU it uses now, and it now costs about the same as with no neighbours. A whole repository check on macOS costs no more than before, and the files picked and everything printed stay the same everywhere. On volumes other than APFS, HFS+, ext4, Btrfs, XFS and tmpfs, a folder is still read in full as before.
- **Every worker thread takes files from the start of a run** ([#300](https://github.com/ryuudotgg/stanza/pull/300))\
  Worker threads now take one file at a time instead of 64, so a run of 64 to 512 files keeps every worker busy where before only one to eight of them got any files. Findings, fixes and their order are unchanged, and `STANZA_WORKERS` works as before.
- **`--hunks` keeps up with rewritten header runs and whole-file rewrites** ([#332](https://github.com/ryuudotgg/stanza/pull/332))\
  `--changed --hunks` and `--staged --hunks` check a long run of headers ending in `)`, `else` or `do` that an edit rewrote onto one line with far less work. 1,600 of them used to cost over a thousand times the instructions of the same check without `--hunks`, and now cost barely more, whether the edit changed the headers or the new line repeats them. A file whose every line changed now takes less than half the instructions it did, and one that shrinks or grows by thousands of lines about a quarter. Which lines count as touched stays the same.
- **The npm `stanza` command starts sooner on Intel Macs** ([#343](https://github.com/ryuudotgg/stanza/pull/343))\
  On an Intel Mac the `stanza` command installed from npm now recognizes the machine from its x86_64 system library cache and starts the binary straight away, without running `uname` first. Apple silicon Macs, Linux and other systems start as before.
- **Repositories under non-ASCII folders skip two git processes** ([#324](https://github.com/ryuudotgg/stanza/pull/324))\
  A repository whose path holds a name such as `café` or `日本`, or whose `.git` file or `commondir` points through one, is now found from the files on disk like any other. A `--check` of one file there starts one git process instead of three, no longer asking `git rev-parse` for the root or `git check-attr` for attributes. Which files are selected and what is printed are unchanged.
- **The Stop hook tells the agent what to fix, file by file** ([#364](https://github.com/ryuudotgg/stanza/pull/364))\
  When findings stop an agent's turn, the block reason now opens with `These need a hand fix in the files you changed:`, then lists the findings under each file, in byte order, as `line N: message (rule)`, so a failure reads like any finding, as in `line 1: Unexpected token (parse)`. It names every file the pass rewrote, not only those that still have findings, so the agent reads them again before editing, and closes by pointing to `stanza explain <file>:<line>`. The rule summaries and the column numbers are gone, since each message already says what to change. A path holding a control character, a line or paragraph separator, `"` or `\` prints quoted, as in a finding row. The JSON fields and exit codes are unchanged.
- **`--changed --hunks` skips the diff of excluded files** ([#430](https://github.com/ryuudotgg/stanza/pull/430))\
  `--changed --hunks` no longer diffs a changed file that `linguist-generated`, `-stanza` or `stanza=false` leaves out, so a large generated file costs a hunk run what it costs a run without `--hunks`. A 12,000 line generated file that changed throughout went from about 138 to 37 million instructions. What Stanza reports and fixes stays the same.
- **Plain-name and suffix rules in `.gitignore` no longer slow selection outside git** ([#389](https://github.com/ryuudotgg/stanza/pull/389))\
  Outside git, a `.gitignore` rule that is a plain name such as `dist` or a suffix such as `*.log` is checked without building any matching state, so a long list of them costs little more than no `.gitignore` at all. Other wildcard rules and bracket sets are cheaper too. Selecting 5,000 files under 600 plain-name rules drops from about 13.8 billion instructions to about 1.7 billion, against 1.55 billion with no `.gitignore`. The same files are selected.
- **Help fits an 80 column terminal** ([#417](https://github.com/ryuudotgg/stanza/pull/417))\
  `stanza --help` now fits in 80 columns. Long usage forms, flag descriptions and rule summaries wrap onto indented continuation lines instead of running up to 299 columns, flags sit under a `Flags:` heading with the same indent as the rules, and the Claude Code hook registration prints as indented JSON that pastes into `.claude/settings.json` as is.
- **Hunk runs unbrace a short body whatever blank lines its changed gap holds** ([#434](https://github.com/ryuudotgg/stanza/pull/434))\
  When a changed gap sits in a block of 2 or 3 statements that are all compact once their braces come off, `--fix --changed --hunks` now removes the braces on every statement of that block, as a whole-file `--fix` would, whether or not the changed gap holds a blank line. It used to keep those braces when the changed gap had none, and `--check --changed --hunks` now reports the same braces.
- **Untracked cache and resolved merges no longer add git processes** ([#439](https://github.com/ryuudotgg/stanza/pull/439))\
  A repository with `core.untrackedCache` turned on, or one that has resolved a merge conflict, keeps extra data in its git index. Stanza used to stop reading the index when it found that data, so a hook event for an edited tracked file also started `git ls-files --others` and `git check-attr`, and `--check` on one file started `git check-attr`. Stanza now skips any index data git marks as optional, and these runs start the same git processes as in any other repository. What is selected, reported and fixed is unchanged.
- **Large destructuring patterns check quickly** ([#382](https://github.com/ryuudotgg/stanza/pull/382))\
  A declaration, assignment or parameter list that destructures thousands of names no longer slows `--check` and `--fix` down with every name it adds. A function whose `const [...]` pattern binds 16,000 names drops from about 2.4 billion instructions to about 50 million, and every finding names the same binding it did before.
- **Deeply nested braceless bodies check faster** ([#383](https://github.com/ryuudotgg/stanza/pull/383))\
  A braceless `if`, `for` or `while` nested under thousands of braceless headers, each on its own line, is now measured in time that grows with the depth instead of its square. A check of 8,000 such levels takes about half the instructions it did. Findings and fixes stay the same.
- **Long transcripts cost the Stop pass less** ([#437](https://github.com/ryuudotgg/stanza/pull/437))\
  The Stop pass passes over transcript lines that cannot name a write on their bytes alone, without decoding them, so a long transcript takes about half the instructions it did.
- **Lint configs that set a global stay readable** ([#423](https://github.com/ryuudotgg/stanza/pull/423))\
  Stanza now reads `curly` from a lint config that also sets a global to a plain value, such as `process.env.FOO ??= "1"` or `globalThis.DEBUG = true`. Before, `--fix` kept braces and printed the unread-config notice for it. A config that also loads a local file, or stores one of its own values in a global, still keeps braces.
- **Usage errors point at the help and suggest the flag you meant** ([#379](https://github.com/ryuudotgg/stanza/pull/379))\
  A usage error now prints the problem and then ``run `stanza --help` for usage`` on stderr, in place of the four usage lines. A mistyped flag names the closest flag the command takes, so `stanza --chek src` prints `stanza: unknown flag --chek, did you mean --check?`, and `stanza explain` and `stanza hook` suggest from their own flags. Exit codes are unchanged.
- **Explain prints every line width in whole digits** ([#416](https://github.com/ryuudotgg/stanza/pull/416))\
  `stanza explain` prints a configured width such as `printWidth: 1e21` as `1000000000000000000000` columns rather than `1e+21`, and its note about a config it cannot read now says `cannot read the line width` in place of `could not read the line width`.

### 🐛 Fixed

- **EditorConfig sections with many stars no longer stall a run** ([#209](https://github.com/ryuudotgg/stanza/pull/209))\
  A section header such as `[*a*a*a*a*a*a*a*ab]` in `.editorconfig` used to hold up every run and hook call in the repository for seconds to minutes. Matching a section now takes at most time proportional to the pattern length multiplied by the path length, and every section matches the same files as before.
- **Fix keeps edits made while it runs** ([#207](https://github.com/ryuudotgg/stanza/pull/207))\
  `stanza --fix` and `stanza hook` no longer replace a file that changed after stanza read it, such as one an editor saved mid-run. The file keeps its new text and is reported as `write: changed while stanza ran, left untouched`: `--fix` exits 2, and the Stop hook lists the file in its block reason, so the next run fixes it.
- **An internal error on one file no longer stops the run** ([#212](https://github.com/ryuudotgg/stanza/pull/212))\
  When stanza hits a bug while formatting a file, it leaves that file untouched, reports it as an `error` finding with one `stanza:` line on stderr naming it, formats every other file and exits 2. Before, the whole run stopped with exit 101 and a Rust panic message. `stanza hook` reports the file the same way and exits 1, so the agent is not blocked.
- **Apple silicon runs the Intel package when it is the only one installed** ([#199](https://github.com/ryuudotgg/stanza/pull/199))\
  On a Mac with Apple silicon where only `@ryuugg/stanza-darwin-x64` is installed, as an install from an Intel build of Node.js leaves it, `stanza` now runs that binary under Rosetta. Before, it stopped with `no binary package for darwin-arm64`.
- **Hooks and --changed no longer rewrite .git/index** ([#225](https://github.com/ryuudotgg/stanza/pull/225))\
  `stanza hook`, `--check --changed` and `--hunks` used to let git refresh and rewrite `.git/index` whenever a tracked file had a new timestamp but the same content, so a `git add` running at the same moment could fail with `Unable to create index.lock`. Stanza now has git read a private copy of the index, so the repository's index and any submodule's index stay as they were. The selected files are the same as before.
- **Large lint configs no longer stall a run or exhaust memory** ([#224](https://github.com/ryuudotgg/stanza/pull/224))\
  Reading an ESLint config used to take time or memory that grew with the square of its size in a few shapes: an object spread into many entries, inline `extends` nested deeply, many extended files, many aliases or `exports.x =` assignments, and a `.eslintrc.yaml` line full of ` #` before a lone carriage return. A 90 KB `eslint.config.js` that spreads one 4000 key object into 4000 entries now checks in 43 MB, where it took 900 MB. Every config resolves to the same settings as before.
- **Biome extends chains and shared Prettier options no longer stall a run** ([#226](https://github.com/ryuudotgg/stanza/pull/226))\
  A `biome.json` whose `extends` chain names the same config twice at each level, or a JavaScript Prettier config whose override options share one object twice at each level, used to hold up every run and hook call in the repository for seconds to minutes. Each Biome config in a chain is now merged once per run and each shared options object is scanned once, so the time grows with the size of the config, and every file still gets the line width it did before.
- **Stanza finishes runs under memory limits and from a deleted directory** ([#231](https://github.com/ryuudotgg/stanza/pull/231))\
  Under an address space limit such as `ulimit -v 900000`, `--version`, `--help` and usage errors used to exit 2 without running, and a run whose worker threads could not start exited 2 with a warning per thread. Those commands now run as usual, the run's main thread steps down to a smaller stack when it has to, and worker threads that cannot start leave one warning without changing the exit code. Started from a deleted directory, stanza used to panic with exit 101; it now formats absolute paths as usual and prints `stanza: cannot read the working directory: no such file or directory` with exit 2 for anything that needs that directory, or exit 1 from `stanza hook` when its input has no absolute `cwd`. Any other internal error outside a file now prints one `stanza: internal error:` line and exits 2, or 1 from the hook, in place of a Rust panic.
- **Fix keeps extended attributes, ACLs and owners** ([#223](https://github.com/ryuudotgg/stanza/pull/223))\
  `stanza --fix` and `stanza hook` keep a fixed file's extended attributes and ACLs, and a file owned by another user or group, as when running as root in a container, keeps its owner and is still replaced in one step. A file mounted on its own, as with `docker run -v ./a.ts:/w/a.ts`, is now fixed instead of failing with `EBUSY`. If a write in place fails and the original text cannot be put back, the finding now reads `cannot write: <reason>, restore failed, the file may be truncated`.
- **Runs no longer stall on hosts with broken DNS** ([#229](https://github.com/ryuudotgg/stanza/pull/229))\
  On a machine with no `user.email` or `EMAIL` set, a hostname without a dot and an unreachable DNS server, every `stanza` run and hook call used to wait for the resolver to time out, about 10 seconds each. Stanza now asks git for its settings without letting it look up the hostname, so these runs take milliseconds again.
- **`--hunks` works on any number of changed files** ([#230](https://github.com/ryuudotgg/stanza/pull/230))\
  `--hunks` used to pass every changed file to one `git diff`, so past roughly 16,000 files on macOS or 33,000 on Linux the command line grew too long and the run stopped with `E2BIG: argument list too long`, the pre-commit hook and the Stop hook included. Stanza now asks git about the files in batches and joins the answers, so a codemod over tens of thousands of files gets the same findings and fixes as a small edit. A run over a large edit also needs less memory, since stanza keeps one batch of diff text at a time instead of two copies of the whole diff.
- **Git hooks in linked worktrees respect the root attributes** ([#235](https://github.com/ryuudotgg/stanza/pull/235))\
  When `GIT_DIR` is set, as git sets it for hooks and aliases in a linked worktree, stanza now uses the work tree git itself would use. A `--fix` run from a pre-commit hook there leaves files the root `.gitattributes` marks `linguist-generated` or `-stanza` alone, skips files the root `.gitignore` ignores, and a relative `GIT_DIR` no longer fails on a path in a subdirectory. Before, each file's own directory was taken as the work tree.
- **Interrupting a fix leaves no temp file behind** ([#237](https://github.com/ryuudotgg/stanza/pull/237))\
  A Ctrl-C, a cancelled CI job or a closed terminal during `stanza --fix` or `stanza hook` could leave a `.stanza-<pid>-<hex>.tmp` file next to a source file, which `git add -A` then picked up, and an interrupted write in place could leave a file empty. Stanza now finishes the file it is writing, starts no other, and then stops on SIGINT, SIGTERM or SIGHUP as before, so every file is either untouched or fully fixed. A signal that was ignored when stanza started, as under `nohup`, stays ignored.
- **Deeply nested files are reported instead of crashing stanza** ([#238](https://github.com/ryuudotgg/stanza/pull/238))\
  A file nested hundreds of thousands of levels deep, such as `[[[…]]]`, nested `if` blocks or a long run of `!`, used to abort the run with a stack overflow and exit 134, or take minutes. Stanza now reports such a file with a `parse` finding, `nests more than 10000 levels deep, left untouched`, before parsing it, and formats every other file in the run. The cap is lower when stanza runs on a smaller stack. The deepest file across five real repositories counts 43 levels. A lint or formatter config nested that deep is treated as one that does not parse, so the run goes on.
- **Stanza names files whose names are not UTF-8** ([#241](https://github.com/ryuudotgg/stanza/pull/241))\
  On Linux, a TypeScript or JavaScript file whose name held bytes that are not valid UTF-8 used to be skipped without a word by `--check .`, `--changed` and the Stop hook, named wrongly by `--staged`, and reported missing when named as a path, while a file named with the replacement character could be read in its place. Every source now prints `stanza: name is not valid UTF-8: "bad\377.ts"`, quoting the name as git does, leaves that file untouched and exits 2, or 1 for the hook, and the rest of the run still goes ahead.
- **Stanza skips a FIFO, socket or device named as a path** ([#234](https://github.com/ryuudotgg/stanza/pull/234))\
  A FIFO, socket or device file with a TypeScript or JavaScript extension, named to `--check`, `--fix` or `stanza explain` directly or through a symlink, used to stop the run on a read that never returned. Stanza now prints `stanza: not a regular file: <path>`, exits 2 and goes on with the other paths. Directories, `--changed` and `--staged` pick files as before.
- **Output stanza cannot write exits 2** ([#240](https://github.com/ryuudotgg/stanza/pull/240))\
  When stanza could not write its findings or fixed text, on a full disk for example, the run exited 1, which reads as "findings remain" and hid a parse error's 2. It now exits 2, or 1 for `stanza hook`, after the same `stanza: cannot write output` line. A warning or notice that cannot be written no longer changes the exit code, so a clean run whose stderr is full still exits 0.
- **Stop hooks skip malformed tool calls in a transcript** ([#243](https://github.com/ryuudotgg/stanza/pull/243))\
  When an agent transcript holds a tool call whose name or id is not a string, `stanza hook` on Stop and SubagentStop now skips that call and still limits the check to the files the rest of the transcript wrote. Before, such a name was converted to a string the way JavaScript does, a call with a number id or no id still counted, and a name that was an object with its own `toString` made the hook fail.
- **Line width overrides cover the files their formatter covers** ([#248](https://github.com/ryuudotgg/stanza/pull/248))\

Prettier's `?` and classes count UTF-16 code units and oxfmt's count bytes, so `?.ts` covers `é.ts` under Prettier and `??.ts` does under oxfmt. Prettier also matches a class by its literal spelling, so `app/[id]/page.tsx` covers that route file, and its `excludeFiles` follows Prettier's own name or path rule for each `files` pattern. A Biome include ending in `/` names folders only, as in Biome, so it neither covers nor excludes a file.

A path holding U+2028 or U+2029 is formatted, where before the hook treated those characters as line breaks and skipped the file. A header with spaces before or after it is matched as Codex matches it, and an indented header inside an Update hunk stays a context line, as it is for Codex. A failed patch whose error message quotes Codex's success line between U+2028 characters no longer counts as applied.

  A file whose name begins with U+FEFF is now selected, checked against its `.gitattributes` and reported under its own name. Before, git's listing lost that character from the first name, so a directory run or `--changed` could leave the file out.

  A directory run or `--changed` now names a skipped submodule whose `.gitmodules` name holds bytes outside UTF-8, whatever the locale. Before, under a UTF-8 locale such a submodule went unnamed, and a directory run holding only it said git ignores its files.

  `--changed` now prints `stanza: cannot read <path>` and exits 2 for a changed file under a folder stanza cannot search and for an untracked folder git cannot open, as a path run does, where it used to skip them in silence. A file deleted from the working tree is still skipped without a word.

  A file named `dist\a.ts` is now checked like any other file, where it used to be skipped as if it sat in a `dist` folder. Only `/` separates folders, so `src\dist/a.ts` is no longer skipped either.

  When `--fix` removes a block's braces, blank lines that sat just inside them are removed with them. Before, a blank line could be left between the header and its body, between the body and `else` or `while`, or below the statement as a new gap.
- **A blank line inside a block comment keeps the comment with its statement** ([#307](https://github.com/ryuudotgg/stanza/pull/307))\
  A block comment with an empty line inside it now moves with the statement below it, so `--fix` puts the blank line it adds above the comment, as it does for any other leading comment. Before, the empty line inside the comment counted as a blank line between the comment and the statement, so the gap above was left alone and never reported. Only a blank line between two leading comments, or between the last one and its statement, sets the statement apart.
- **Decorated exported classes start at their decorator** ([#297](https://github.com/ryuudotgg/stanza/pull/297))\
  A decorated `export class` or `export default class` now starts at its first decorator, like a decorated class without `export`. `--fix` puts the blank line above the decorator instead of between the decorator and `export`, adds the blank line after a multi-line class, and a `// stanza-ignore` above the decorator holds the class's gaps. A class written as `export @dec class` still starts at `export`.
- **An empty path argument stops the run instead of selecting the folder** ([#286](https://github.com/ryuudotgg/stanza/pull/286))\
  An empty path given to `--check` or `--fix`, alone, beside other paths or after `--`, used to select every file in the working directory, so `stanza --fix a.ts ""` rewrote the whole folder. Stanza now prints `stanza: "" is not a path, pass . for the current folder`, exits 2 and reads or writes no file, as `git ls-files -- ""` refuses the same pathspec.
- **The walk without git ignores what git ignores** ([#298](https://github.com/ryuudotgg/stanza/pull/298))\
  Outside a git work tree, or with git missing from `PATH`, the directory walk now reads a `.gitignore` only when it is a regular file. A `.gitignore` that is a socket or a link to a folder used to stop the run with `cannot read .gitignore` and exit 2; it is now skipped. The walk also strips a byte order mark at the start of a `.gitignore`, treats a pattern holding an unknown class such as `[[:foo:]]` as matching nothing, lets `**\/` cross folders and matches the first character of a reversed range such as `[z-a]`, all as `git check-ignore` does.

  When `--fix --changed --hunks` removed the braces of a body that started with a blank line, the next run could count the joined line as an edit and remove a blank line outside the first run's scope, such as the one above the function's closing brace. The next run now counts the joined line and the blank line it absorbed as unchanged, so a repeated run changes no byte.
- **The npm command starts through a working runtime and exits with its own status** ([#285](https://github.com/ryuudotgg/stanza/pull/285))\
  When the platform package holds something other than a regular executable file, `stanza` now falls back like a missing binary and exits 1 for `stanza hook` and 2 otherwise, where the shell used to exit 126. With no platform binary to run, it starts Bun or Node.js only after that runtime answers `--version`, so a version manager's `bun` shim with no Bun behind it no longer stops a machine that has Node.js. `sh stanza` run inside `node_modules/.bin` also finds its package now.

  When stdout or stderr is a non-blocking pipe, stanza now waits for the reader to drain a full pipe instead of stopping.   When `--fix` writes a file in place and cannot open it, the `write` finding says `cannot write: <reason>` and the file is left as it was. That warning now appears only when a write failed after the file was cut.

They now take the same file the system opens, and so does `stanza explain`. - **A stanza-off in a decorator callback ends with the callback** ([#322](https://github.com/ryuudotgg/stanza/pull/322))\
  A `stanza-off` inside the callback of a decorator now stops at the end of that callback, like one in any other function. Before, it ran to the end of the file in two cases: a TypeScript parameter decorator such as `constructor(@d(() => { ... }) x: T)` on a parameter that was not optional, and a class decorator written before `export`. Everything after it kept braces and blank lines `--fix` should have changed.
- **A changed leading comment scopes a TypeScript file like a JavaScript one** ([#322](https://github.com/ryuudotgg/stanza/pull/322))\
  With `--changed --hunks` or `--staged --hunks`, editing a comment above the first statement of a `.ts` file now checks the gaps of the top level statements, as it already did for `.js`. Before, the `.ts` file reported nothing for that change.
- **TypeScript lint configs passed into calls keep braces** ([#325](https://github.com/ryuudotgg/stanza/pull/325))\
  `--fix` no longer removes braces when a TypeScript lint config names its settings in a parameter property default such as `private p = config`, a parameter decorator or an abstract member key inside a call Stanza cannot read. Those settings may be changed by the call, so braces stay and the unread-config notice names the config. A parameter property named like the config, such as `public config`, now hides the outer binding the way TypeScript scopes it, so it no longer keeps braces with a false notice. A parameter default also no longer hides the config when the function body declares a `var` of the same name.
- **A leading `./` anchors oxlint and legacy ESLint overrides** ([#370](https://github.com/ryuudotgg/stanza/pull/370))\
  An override pattern that starts with `./` in an oxlint config or a legacy ESLint config now matches only from the config's own directory, as oxlint and ESLint read it. Before, `./*.ts` also reached `src/a.ts`, so an override that turns `curly` off there let `--fix` remove braces the root config enforces.
- **Biome `extends` reads every base as JSON** ([#392](https://github.com/ryuudotgg/stanza/pull/392))\
  A Biome config and each file it `extends` are now read as JSON with comments and trailing commas, whatever the file's suffix, as Biome reads them. A relative `extends` path is taken exactly as written, with no extension added, and Stanza follows at most 10 nested `extends`. Before, an `extends` to a `.js` file ran it as JavaScript, so a JavaScript base that turned `useBlockStatements` off let `--fix` remove braces, and a `.js` base holding JSON kept braces with a false notice. A base that is not JSON, cannot be found, sits in a cycle or past the 10th level now keeps braces with the notice naming the config, even when a later override turns the rule off, since Biome rejects the whole config then.
- **Misplaced Biome brace settings no longer decide braces** ([#402](https://github.com/ryuudotgg/stanza/pull/402))\
  Stanza reads Biome's `useBlockStatements` only from `linter.rules.style`, and its group and root switches only under `linter.rules`, at the top of `biome.json` or inside an override. A brace setting anywhere else, such as a top-level `style` block, a bare `useBlockStatements` key or a `rules` block outside `linter`, used to turn braces on or off silently even though Biome rejects that config. Such a config is now unknown: braces stay and the unread-config notice names it.
- **Biome extends chains stop at 10 files for the width** ([#421](https://github.com/ryuudotgg/stanza/pull/421))\
  `--fix` reads a Biome config's width through at most 10 extended files, as Biome does. A longer chain, which Biome refuses, used to give the width at its end and could join a guard; now Stanza prints a notice that it cannot read the line width from that config and takes the next source, without reading the rest of the chain.
- **Long brace patterns in lint overrides keep braces quickly** ([#390](https://github.com/ryuudotgg/stanza/pull/390))\
  A lint override whose `files` pattern repeats brace groups thousands of times, such as `{a}{a}{a}...`, used to take seconds and hundreds of megabytes per run, then remove braces the override may enforce. Expanding a pattern now costs time and memory in proportion to its length, and a pattern too large to expand within that bound counts as one Stanza cannot read, so an override that turns `curly` on keeps braces.
- **Stop checks files the agent committed** ([#366](https://github.com/ryuudotgg/stanza/pull/366))\
  `stanza hook` on Stop and SubagentStop now checks every file the agent wrote this session that still exists and that git does not ignore, whether or not it differs from HEAD, so committing a file before the turn ends no longer hides a finding it still has. Before, a written file with no change against HEAD was skipped. With `--hunks`, a written file with no change against HEAD is still left alone, and one changed since keeps its changed-line scope. The pass after a Write, Edit or Codex patch follows the same rule, so it also fixes a written file whose content matches HEAD. A Stop without a transcript Stanza can read still takes only changed files.
- **EditorConfig sections apply to the files the formatter applies them to** ([#391](https://github.com/ryuudotgg/stanza/pull/391))\
  Under Prettier, an `.editorconfig` section now sets the width and tab width for exactly the files Prettier applies it to: `[a\ b.ts]` and `[a\*.ts]` read their escapes, `[{a}.ts]` matches only `{a}.ts`, `[{1..3}*.ts]` matches `12.ts`, and `[src[!x]1/b.ts]` no longer matches `src/1/b.ts`. Under oxfmt, which matches sections its own way, a section that oxfmt and EditorConfig answer differently for a file, such as `[a.ts]` or `[{a,b}.ts]` for `src/a.ts`, makes Stanza report that `.editorconfig` as unread and take the next width source instead of guessing. A section pattern Stanza cannot match exactly, such as an extglob, a POSIX class or a numeric range of more than 256 values, now gets the same notice when the section sets a width or tab key.
- **Explain quotes each source line once** ([#427](https://github.com/ryuudotgg/stanza/pull/427))\
  `stanza explain` quotes a source line once per answer, even when several gaps, braced bodies or walls on that line would each quote it. A minified line that opens 1,600 bodies now prints its source once rather than 1,600 times, so the answer stays a few hundred kilobytes instead of 18 MB. Every section still prints its own rule and result.
- **Explain notes only the braces that bear on a gap** ([#418](https://github.com/ryuudotgg/stanza/pull/418))\
  `stanza explain` on a gap now notes a brace removal only when the braces sit inside one of the gap's two statements, or inside a block of 2 or 3 statements where `short-body` judges every statement. Before, a gap at module level named braces inside any function in the file, so a gap decided by `use-join` beside an unrelated function claimed it was decided after `--fix` removed that function's braces.
- **`--changed --hunks` checks files with a clean filter** ([#380](https://github.com/ryuudotgg/stanza/pull/380))\
  A file whose `filter` attribute runs a clean filter now counts as changed throughout under `--changed --hunks`, as it already did under `--staged --hunks`. Before, git reported the edited lines in the filtered text, so an edit could be missed or the wrong lines checked whenever the filter added or removed lines, and the Stop hook let it through.
- **Guards with emoji, combining marks or tabs join only when the formatter keeps them** ([#431](https://github.com/ryuudotgg/stanza/pull/431))\
  `--fix` now measures a joined guard the way the governing formatter measures it, character by character and tab by tab, so it no longer joins a line the formatter then splits or keeps apart one the formatter would join. Before, Stanza used Bun's character widths and tab stops for every formatter, so `if (a) log("भारत");` joined at a width of 20 although Prettier, oxfmt and Biome all split it there. Prettier and oxfmt count an emoji sequence such as 👍🏽 as 2 where Biome adds up its parts, Prettier counts a tab after the indentation as nothing, and with no formatter Stanza measures as Prettier does.
- **Each formatter's `.editorconfig` is read the way it reads it** ([#373](https://github.com/ryuudotgg/stanza/pull/373))\
  Under Biome, `stanza --fix` no longer takes the line width from `max_line_length` or the tab width from `tab_width`: it takes only `indent_size`, as Biome does, so a guard Biome would split stays split, and an `.editorconfig` Biome would refuse, such as one with an `indent_size` above 24 in any section, is reported as unread. Under oxfmt it reads the one `.editorconfig` beside the oxfmt config, or beside the `package.json` that lists oxfmt, which is the file oxfmt reads when run from that directory, rather than the one nearest the file. Under Prettier, a regular file or a link named `.hg` no longer stops the search for `.editorconfig`.
- **Marker text inside a string no longer marks a file generated** ([#393](https://github.com/ryuudotgg/stanza/pull/393))\
  A line such as `// @generated` that sits inside a template literal, or inside a quoted string continued with a backslash, used to make Stanza skip the whole file as generated. Only a real comment in the first ten lines marks a file generated now, so these files are checked and fixed like any other.
- **A git failure in one repository no longer stops the hook in the others** ([#377](https://github.com/ryuudotgg/stanza/pull/377))\
  When the agent wrote files in several repositories and git failed in one of them, such as on a corrupt index, `stanza hook` used to fix nothing at all. It now still fixes and reports the files in the other repositories, writes the failure on stderr and exits 1, so Claude Code and Codex show a notice beside the usual block decision or read-again context.
- **The hook formats a Write for the file the agent writes** ([#401](https://github.com/ryuudotgg/stanza/pull/401))\
  A relative `Write` path under a symlinked `cwd` is now joined to `cwd` as Claude Code and Codex join it, so `../a.ts` names the `a.ts` beside the link that the agent writes, with that file's settings, `--hunks` check and opt-out. The hook used to step up from the folder the link points to and format the content for another file. `Edit`, `MultiEdit` and `apply_patch` paths already worked this way and keep doing so.
- **Hunk runs keep braces short-body cannot join** ([#396](https://github.com/ryuudotgg/stanza/pull/396))\
  `--fix --changed --hunks` used to remove braces outside the changed lines whenever a changed gap with a blank line sat in a list of 3 or fewer statements, even at the top level of a file or beside a statement that spans several lines, where `short-body` never joins the list. It now reaches past the changed lines only in a block of 2 or 3 statements that are all compact once their braces come off, and `--check --changed --hunks` reports the same.
- **import.meta and new.target read no binding** ([#371](https://github.com/ryuudotgg/stanza/pull/371))\
  A binding named `meta` or `target` no longer joins to a statement that only uses `import.meta` or `new.target`, since neither reads a variable. Before, `const meta = load();` above a blank line and `if (import.meta.url)` got a `guard-join` finding, and `--fix` removed the blank. A statement that reads `meta` or `target` itself still joins.
- **The hook still fixes absolute paths when its working directory is gone** ([#387](https://github.com/ryuudotgg/stanza/pull/387))\
  When the `cwd` a hook event names no longer exists, `stanza hook` used to skip every file. It now fixes the files a successful PostToolUse call, a Stop transcript or a SubagentStop transcript names by absolute path, and prints those paths in full. Under a missing `cwd`, a relative tool path and a Stop without a transcript Stanza can read still change no file.
- **A repository inside a folder outside git keeps its attributes** ([#367](https://github.com/ryuudotgg/stanza/pull/367))\
  Running `stanza --check .` or `--fix .` in a folder that is not in git now hands each repository found below it to git, so that repository's ignore rules, `-stanza` opt outs and `linguist-generated` marks apply exactly as when you pass its path. Before, the walk entered the repository like any other folder, applied only `.gitignore` files, and checked and fixed files its `.gitattributes` excludes. A `.gitignore` outside the repository can still skip its folder, but no longer reaches the files inside it. A folder git refuses as a repository, such as one holding an empty `.git`, now prints git's error and makes the run exit 2, as passing its path does. With git missing from `PATH`, the walk is unchanged.
- **Lint overrides scoped to file names decide braces per file** ([#413](https://github.com/ryuudotgg/stanza/pull/413))\
  The braces rule now reads each file against the lint overrides whose patterns match that file's own path. An override that turns `curly` or `useBlockStatements` on for `**/*.config.ts` keeps braces in `src/vite.config.ts` and lets `--fix` remove them from `src/a.ts`, and an override that turns the rule off for `**/*.test.ts` removes braces only in test files. Exclusions through ESLint `ignores` or `excludedFiles`, oxlint `excludeFiles`, and `!` patterns in Biome `includes` now leave out exactly the files they name when Stanza can match the pattern exactly, and a pattern it cannot match still keeps braces. Before, a file-name pattern counted for every file of its extension in the folder, so braces stayed everywhere.
- **Braces come off a body that a closing brace follows on the same line** ([#422](https://github.com/ryuudotgg/stanza/pull/422))\
  A single statement body with no trailing semicolon, such as the `{ b() }` in `function f() { if (a) { b() } }`, used to keep its braces when the `}` that ends the statement followed on the same line. Bodies nested that way came off one level per internal pass, so a deep nest took time that grew with the square of its depth, and `--fix --changed --hunks` could need a second run. Every level now comes off in one pass, since no code can continue a statement past a `}`, and a check of 1,600 bodies nested on one line takes under a hundredth of the instructions it did.
- **A path that vanishes during selection no longer stops the run** ([#428](https://github.com/ryuudotgg/stanza/pull/428))\
  When a folder or file passed to `stanza --check` or `--fix` disappears or cannot be resolved after git has listed it, Stanza prints a `cannot read` line for that path and still checks every other path. Before, the whole run stopped with `file selection failed` and checked nothing.
- **A config's own `require` no longer reads as Node's** ([#365](https://github.com/ryuudotgg/stanza/pull/365))\
  When a lint config declares, imports or assigns its own `require`, Stanza no longer treats `require("./base.cjs")` in it as loading that file. It cannot tell what such a call returns, so braces stay and the unread-config notice names the config. Before, `--fix` read the named file and could remove braces the config enforced.
- **Shared Prettier and Biome configs set the width** ([#411](https://github.com/ryuudotgg/stanza/pull/411))\
  `--fix` takes the line width, tab width and overrides from a shared Prettier config that `package.json` or `.prettierrc` names by a string, and from a Biome config that `extends` a package export. It used to print a notice that it could not read the line width and fall back to the next source, so a guard the formatter keeps split could be joined.
- **A folder inside a skipped folder stays skipped** ([#410](https://github.com/ryuudotgg/stanza/pull/410))\
  In a git repository, `stanza --check dist` and `stanza --check .` run inside `dist` now skip the files there, as `stanza --check .` and `stanza --check dist/a.ts` already did, and print that its files are always skipped. Before, passing the folder itself, or running from inside it, checked and fixed every file in it. Setting the `stanza` attribute still opts those files in, and a folder below it that git cannot open now prints its `cannot read` line instead of leaving its files out without a word. Outside git the folder you pass is still where the skipped names start counting.
- **Configs that share an import chain read the same in any order** ([#412](https://github.com/ryuudotgg/stanza/pull/412))\
  When two lint or Prettier configs import the same chain of files, each one now gets the answer it gets when read alone. Before, a config that reached past the 32 file import limit could make a second config that enters the chain lower down read as unknown too, so `--check` kept braces and named both configs in the notice even though the second one turns `curly` off.
- **Configs that import back into another config read the same in any order** ([#424](https://github.com/ryuudotgg/stanza/pull/424))\
  When a shared file imports from a lint config that also extends it, only that config now reads as unknown. A second config that imports or extends the same shared file gets the answer it gets when read alone. Before, whichever config was read first decided both, so `--check` could keep braces for the second config and name it in the notice even though it turns `curly` off.
- **`--check --staged` ignores unstaged attribute edits to filtered files** ([#409](https://github.com/ryuudotgg/stanza/pull/409))\
  A staged file with a `filter` attribute is now converted with every attribute the index holds. Before, an unstaged `.gitattributes` edit that only added `working-tree-encoding`, `text`, `eol`, `crlf` or `ident` changed the bytes `--staged` checked, so a UTF-16 encoding in the working tree turned a staged braces finding into a parse error.
- **--staged no longer rewrites .git/index** ([#420](https://github.com/ryuudotgg/stanza/pull/420))\
  `--check --staged` used to let git rewrite `.git/index` when a staged file had a newer timestamp, or when a filtered file's staged attributes differ from the work tree's and Stanza writes a tree to read them, so a `git add` or `git commit` running at the same moment could fail with `Unable to create index.lock`. Git now works on private copies of the index for both steps, as `--changed` already did, and the repository's index stays as it was. The files checked and the findings are the same as before.
- **Tab indented bodies join their header when braces come off** ([#368](https://github.com/ryuudotgg/stanza/pull/368))\
  When `--fix` removes braces from a body that fits, it now joins the body onto its header line with one space whatever whitespace sat between them. Before, a body indented with tabs stayed on its own line unless a space sat between the header and its brace, so a brace on a line of its own, a brace after a tab, or `){` kept the body apart while the same code indented with spaces joined.
- **Escaped transcript keys count on Stop** ([#437](https://github.com/ryuudotgg/stanza/pull/437))\
  A Stop pass now reads keys and values a transcript or rollout spells with unicode escapes, so a failed Edit whose result spells `is_error` that way no longer counts as a write, and an escaped `tool_use` or `item_completed` now names its file.
- **Stop reads a transcript in the format it starts in** ([#437](https://github.com/ryuudotgg/stanza/pull/437))\
  Stanza reads the file as a Claude Code transcript or a Codex rollout from its first record that identifies one, so a Codex record late in a Claude Code transcript no longer makes Stop read it as a rollout, and a rollout that holds only `session_meta` changes no file instead of falling back to every changed file in the repository.
- **ESLint patterns Stanza reads unlike ESLint keep braces** ([#378](https://github.com/ryuudotgg/stanza/pull/378))\
  In ESLint `files`, `ignores`, `excludedFiles` and override patterns, a brace group without a comma such as `{src}`, a range such as `{1..3}`, a backslash, an empty path segment, and a `.` or `..` segment now leave Stanza unsure which files the pattern covers, so braces stay. `--fix` keeps braces where such a pattern turns `curly` on, and such a pattern can no longer turn `curly` off. Before, `{src}/**` reached `src` although ESLint reads it as a directory literally named `{src}`, and `src/{1..3}/**` reached no file. oxlint still reads `{src}` as `src`.
- **A `.gitignore` git cannot read fails a repository run** ([#419](https://github.com/ryuudotgg/stanza/pull/419))\
  Inside a repository, a path run or `--changed` now prints `stanza: cannot read <path>: <reason>` and exits 2 for a `.gitignore` git cannot read, as the walk without git already did. Before, the run went ahead without that file's rules and could check or fix files it meant to skip. This holds in an always skipped folder the `stanza` attribute opts back in too, where `--changed` now also reports a folder git cannot open, as a path run does. A symlinked `.gitignore`, which git does not follow, is still not an error, and the hook still says nothing about an unreadable one.
- **A submodule path key with no value names no submodule** ([#362](https://github.com/ryuudotgg/stanza/pull/362))\
  A directory run or `--changed` no longer reports a skipped submodule for a `.gitmodules` entry whose `path` key has no value. Before, such a key was read as its own path, so a gitlink at a folder spelled like the key, such as `submodule.a.path`, was named as a skipped submodule. Entries with a real `path = <dir>` are still named.
- **A symlinked folder outside git is walked from where it leads** ([#381](https://github.com/ryuudotgg/stanza/pull/381))\
  Outside git, `stanza --check link real` with `link` pointing at `real` used to report each file twice, once under each name, and a pooled `--fix` over both could stop with `write changed while stanza ran`. A folder argument outside git is now walked from its real location, as one inside a repository already is: each file is checked once under its real name, an absolute path through a symlinked folder such as `/tmp` prints the same relative name, and the `.gitignore` files above the link's target apply.
- **Braces stay when a lint config changes a wrapped or tagged value** ([#442](https://github.com/ryuudotgg/stanza/pull/442))\
  A lint config that changes its own value through a wrapped receiver, such as `(config as any[]).push(strict)`, `config!.push(strict)` or an alias like `const typed = config as any[]`, or that hands the config to a tag as in ``add`${config}` ``, now keeps braces and prints the unread-config notice. Before, `--fix` read the config's original `curly` setting and could remove braces the config enforces.
- **YAML ESLint configs answer like their JSON twins** ([#405](https://github.com/ryuudotgg/stanza/pull/405))\
  `.eslintrc.yaml`, `.eslintrc.yml` and an extensionless `.eslintrc` are now parsed as a whole, so `rules`, `root`, `extends` and `overrides` decide braces exactly as they do in `.eslintrc.json`. Before, Stanza scanned YAML lines for `curly`, so an override that extends `eslint:all` for `*.ts` over a root `curly: off` let `--fix` remove braces ESLint enforces, and `{rules:{curly:"off"}}` in `.eslintrc` read as off although ESLint reads `curly:"off"` there as a key. An extensionless `.eslintrc` is read as JSON with comments first, then as YAML. A YAML file that uses anchors, tags, multiline or block scalars, more than one document, duplicate keys or other syntax outside the plain subset Stanza reads, even under an unrelated key, now keeps braces with the notice naming that config.

## 0.3.3

### Skip unnecessary Git attribute checks

Path runs, `--changed`, `--stdin <path>`, `explain` and hooks skip the Git attribute subprocess when no attribute source can apply to the files, no `attr.*` config is set, and every `GIT_*` variable set is one Stanza knows cannot affect attribute lookup. Anything else, including `GIT_ATTR_SOURCE` or an attributes path Stanza cannot rebuild, still asks Git, and `--staged` always asks Git.

### Explain accepts paths starting with a dash

`stanza explain` now accepts `--` before a location whose path starts with `-`. Flags are parsed only before the first `--`; arguments after it are literal.

### Codex SubagentStop checks the subagent's own writes

A Codex SubagentStop hook now reads the subagent rollout at `agent_transcript_path` and checks the files that subagent patched, as Stop does for a Codex session. Before, it read only Claude Code transcripts, so a Codex subagent's files went unchecked.

### Explain counts lines like an editor

`stanza explain` treats a final newline as the end of the last line rather than the start of another, so a line beyond the end of the file now gets the right count, such as `a.ts has 2 lines, not 3` for a two line file ending in a newline, and an empty file has 0 lines.

### Fewer Git processes when a Git config uses include or includeIf

Finding the repository root no longer starts an extra Git process when a Git config file uses `include` or `includeIf`, so a check in such a setup starts as many Git processes as one without them. A repository whose path ends in a space also works now, where `--check` used to exit 2 with "cannot change to" and the path without its trailing space.

### Lost worker threads are reported and their files still formatted

When a run that uses worker threads loses one, because it fails to start or dies after taking files, Stanza reports the loss with a `stanza:` line on stderr and exits 2, and still prints the same findings and writes the same files as a serial run. Before, a worker that failed to start went unreported and a worker that died after taking files hung the run. Runs that start no worker thread, such as a single file or `STANZA_WORKERS=0`, no longer load the worker machinery, so they start slightly faster.

### Walls with a comment inside a joined group are reported again

`wall` again reports a run of joined statements, such as six guards, when a comment sits directly above one of them, because a blank line between that comment and its statement survives `--fix` and splits the run. Runs that no kept blank line can break stay unreported, and `--fix` output is unchanged.

## 0.3.2

### Release binaries start faster

The binaries on the GitHub release now ship precompiled bytecode, so each run skips parsing Stanza's own code and starts a few milliseconds sooner. Each binary is about 2 MB larger. Output is unchanged.

### Whole repo runs look up each directory once

`--check` and `--fix` resolve a directory's real path, look for config files in it and read the `package.json` files above it once per run, rather than once per file. Large repos spend less time on file system calls. Output is unchanged.

### Help lists all supported hook events

`--help` now lists Stop, SubagentStop, PostToolUse on Edit, MultiEdit and Codex
`apply_patch`, and PreToolUse on Write. The `--json` description no longer says
it is for hooks.

### The hook asks git only about the files you wrote

`stanza hook` asks git only about the files an edit or a Stop transcript names, rather than walking the whole worktree, so hooks stay fast in large repos. Results are unchanged.

### Fewer git processes during repository discovery

The CLI and hooks find plain repository roots in process and reuse each directory lookup within an invocation. Worktrees, submodules and uncertain configurations still use git.

### SubagentStop checks only the subagent's own writes

`stanza hook` now uses `agent_transcript_path` for SubagentStop without checking the main session or other agents. Missing, unreadable and empty agent transcripts leave repository files untouched and exit silently. Stop keeps its whole-session scope.

### Joined guards and declarations no longer report unavoidable walls

`wall` no longer reports groups of six or more statements that join rules keep together. Shorter joined groups still count toward clearable walls, and separate walls in the same body still report. Join rules and fixed output stay unchanged.

### Large CLI runs use worker threads

`--check` and `--fix` format large file selections on worker threads. Output and fixed files stay identical to serial runs. Hooks and small selections stay on the main thread.

## 0.3.1

### Faster checks on large repos

`--check` and `--fix` walk each file's syntax tree with less work per node, so a whole repo run finishes sooner. Results are unchanged.

### Brace answers no longer depend on which directories ran first

A lint config too large to read in time is reported as unread whether or not another directory in the same run already read a shared config it extends. Before, running `--check` or `--fix` on several directories at once could settle braces for such a config that a run on its directory alone left unread.

### `--fix` parses each rewritten file once fewer

`--fix` no longer parses a rewritten file a second time when Stanza already parsed that exact text, so fixing a large repo is faster. Fixed text that does not parse is still left untouched.

### Faster checks and fixes across many files

Once a run has parsed about half a megabyte of source, Stanza reads the parser's syntax tree from a shared buffer instead of decoding JSON, in the release binaries and in installs from npm or bunx. Output is unchanged, and short runs such as the agent hooks stay on JSON. A file the faster path cannot handle, such as a very deep expression or one over a million characters, is parsed the old way on its own. `STANZA_RAW_TRANSFER=0` turns the faster path off.

## 0.3.0

### Compressed release binaries

Every GitHub release now carries a `.tar.xz` archive per platform, a quarter to a third of the raw download, listed in SHA256SUMS. The raw binaries stay where they were.

### The hook returns at once when there is nothing to format

`stanza hook` now answers an event it ignores, or an edit that touched no TypeScript or JavaScript file such as `package.json`, without running git or loading the formatter. Those calls now take about as long as `stanza --version`.

## 0.2.0

### Blank line rules apply at module top level

The blank line rules now cover the gaps between top level statements, not just the ones inside blocks. A `let` that the function below it reads joins that function and gets a blank line above it, a multi-line statement gets a blank line after it, and a run of six statements is reported as a wall. `export const` and `export function` count as the declaration they export. Imports and re-exports stay one group, with no blank line forced between them and no wall reported for them. [short-body](https://stanza.ryuu.gg/rules/short-body) skips the top level, so a short file loses a blank line only when another rule asks for it.

## 0.1.2

### JSX element names count as uses of a binding

A component used as a JSX element, such as `<Row />` or `<Icons.Close />`, now counts as a read of `Row` or `Icons`. Its declaration joins the statement that renders it, the same way any other use would. Lowercase intrinsic elements like `<div>` are not treated as bindings.

## 0.1.1

### Generated variants are skipped for every extension

`.gen` files are now skipped for every JavaScript and TypeScript extension (`.gen.ts`, `.gen.tsx`, `.gen.mts`, `.gen.cts`, `.gen.js`, `.gen.jsx`, `.gen.mjs`, `.gen.cjs`), and `.min` files for `.js`, `.mjs` and `.cjs` (#106).
